# Апгрейд MinIO → SeaweedFS

Для существующих инстансов со встроенным MinIO. Новая установка или внешний `AIQSA_S3_ENDPOINT` не требуют переноса. Все команды выполняются из каталога установки, с её прежними `.env`, Compose overrides и именем проекта.

## Перед началом

- Назначьте окно обслуживания; до завершения проверки не допускайте пользователей. Завершите текущие загрузки: незавершённые multipart-загрузки потребуется начать заново.
- Сделайте согласованную резервную копию PostgreSQL и MinIO при остановленных приложении и фоновых писателях; оставьте их остановленными до миграции. Отдельно сохраните `.env`, overrides, текущий релиз и digest образа для отката.
- Нужны Docker Compose ≥ 2.29.7, сохранённый на хосте образ MinIO и свободное место: размер старого хранилища + 10% + 1 GiB. Не удаляйте старые образы и volumes.
- Если overrides меняли `/data` сервиса `minio`, уберите этот mount из `minio` и подключите **тот же источник** к `minio-legacy:/data` и `storage-init:/legacy:ro`. Новый `seaweedfs:/data` должен использовать отдельное хранилище. Уберите MinIO-specific `image`/`command` overrides: `minio` теперь S3-релей.
- Профиль `storage-migration` не должен быть включён в `COMPOSE_PROFILES`.

## Выполнение

1. Дождитесь публикации релиза с SeaweedFS и его образов. Замените `vX.Y.Z` ниже на согласованный релизный тег. До переноса **не запускайте обычный `docker compose up -d`**.

   ```sh
   git fetch origin --tags
   git switch --detach vX.Y.Z
   ```

   Сверьте образы с этим релизом: для основного образа задайте в `.env` `AIQSA_IMAGE=ghcr.io/insciqq/aiqsa:X.Y.Z` (без `v`). Если остальные образы закреплены на старых версиях через `.env` или overrides, обновите их по ссылкам/digest из release notes. Сохраните остальные настройки и секреты.

   ```sh
   docker compose pull
   sh scripts/migrate-minio-to-seaweedfs.sh --dry-run
   ```

   Продолжайте только после успешного dry run. Сохраните напечатанные имена `Legacy MinIO data` и `New SeaweedFS data`. При ошибке выполните указанный `Next step` и повторите проверку.

2. Запустите перенос:

   ```sh
   sh scripts/migrate-minio-to-seaweedfs.sh
   ```

   Скрипт остановит стек, применит миграции БД, скопирует объекты с проверкой размера, SHA-256 и ContentType, запишет маркер и запустит стек. Старое хранилище сохраняется. Ожидайте `Migration complete` и код выхода `0`.

3. Проверьте маркер:

   ```sh
   sh scripts/migrate-minio-to-seaweedfs.sh status
   ```

   Для перенесённой установки ожидаются `marker=valid`, `marker_source=migrated` и `migrated_missing_references=0`. При другом результате остановите стек (`docker compose stop`) и разберите причину до допуска пользователей.

4. Завершите переключение, в том числе после прерванного запуска, который уже записал маркер:

   ```sh
   docker compose --profile storage-migration rm -sf minio-legacy
   docker compose up -d
   docker compose ps -a
   ```

   Проверьте: `app` — `healthy`, `storage-init` — `Exited (0)`, `minio-legacy` отсутствует. Откройте несколько старых вложений и документов Knowledge; загрузите и скачайте новый небольшой файл. После этого допускайте пользователей.

5. Переключите резервное копирование на **New SeaweedFS data вместе с PostgreSQL**. Старый MinIO сохраняйте до проверки новых резервных копий.

## Если возникла ошибка

- Ошибка копирования: устраните причину и повторите скрипт. Уже перенесённые объекты будут проверены перед пропуском. Не удаляйте новый volume для «повторного старта».
- `Already migrated` означает наличие маркера, но не подтверждает запуск приложения: выполните шаги 3–5.
- `storage_migrate_source_empty_with_references`: текущий скрипт может так отказать при пустом bucket с незавершёнными загрузками. Не удаляйте ссылки из БД; передайте ошибку сопровождающему для исправления миграции.
- Неверный/чужой маркер, отсутствующий образ или несовпадение mounts: остановитесь и проверьте проект, overrides и старое хранилище. Не обходите проверки.
- Скрипт переносит обычный приватный bucket без versioning, encryption и object lock. Если проверка отказала из-за этих настроек, согласуйте отдельную процедуру; не отключайте защиту ради прохождения проверки.
- Для диагностики: `docker compose logs storage-init seaweedfs minio app`. Перед передачей логов удалите приватные данные.

## Откат

Сначала остановите текущий стек: `docker compose --profile storage-migration stop`. Используйте прежний релиз и образ по сохранённому digest, согласованную резервную копию БД, MinIO, `.env` и overrides. Простое переключение обратно на старый MinIO не переносит новые данные из SeaweedFS. Если после миграции были записи, сначала согласуйте их сохранение; не запускайте старую установку поверх текущей БД и не удаляйте ни одно хранилище.
