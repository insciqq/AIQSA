# MEMORY

Owner: Native Memory maintainers
Scope: Personal Memory authority, evidence, retrieval, learning, and lifecycle.

The cross-cutting safety boundary is in [Critical invariants](CRITICAL_INVARIANTS.md). Exact policies, limits, prompts, identities and job manifests belong to [Memory code](../lib/server/memory/), not this document.

## Product And Authority

All five Personal Memory preferences are enabled at account creation. Later user choices remain authoritative across login, bootstrap and upgrades. Assigning a working System Model with the required verified capabilities authorizes the corresponding Memory operations; there is no separate administrator or user egress consent. Each dispatch still validates the exact configured model, connection, credential and role. Model changes affect future admissions and never retarget accepted executions. Optional embedding and reranking failures preserve the supported local fallback; an explicit user pause remains authoritative.

Personal Memory is user-global. Saved Memories remain directly manageable while Memory is paused; pausing stops new use and work without deleting retained data. Archive is organization only. Resume admits only messages after its server-owned cutoff, never automatic historical backfill. Temporary and Project chats create or receive no Memory context, sources, bindings, counters or jobs. Legacy non-global and Project data is not silently broadened into Personal Memory. Public shares strip the entire private Memory surface.

Ordinary non-empty answers retain deterministic retrieval from the locally sanitized original query, with every enabled source family eligible. They dispatch no System Model read planner or query resolver. Unavailable or invalid optional embedding, sorting, temporal or aggregation signals cannot suppress already admitted evidence or authorize mutations. A valid pure explicit action may skip ordinary retrieval; an action-plus-answer request retains it. Admission exhaustion continues the ordinary answer without Memory, and child budgets reserve time for local retrieval and packing.

In-chat management requires an explicit current-turn directive, a bounded provider-free gate, then a forced-strict decision proven against the exact authoritative current user message and exact owned target where applicable. The gate grants no mutation authority. `/memory` supplies a language-neutral command boundary; reset still requires confirmation. The answer model has no Memory mutation tools. Earlier turns, quotations, assistant text, retrieved content, attachments, tool output and client metadata cannot authorize a mutation or attest a user fact.

Inbound Memory MCP is a separate delegated owner-command boundary. An active owner-bound OAuth grant authorizes only the exact validated facts-only tool call; invalid or revoked grants cannot infer or replay mutations. Search exposes current global facts through the native retrieval path, excluding history, patterns and profile synthesis. It creates no synthetic chat/run or System Model call; utility work has its own content-free execution owner and the external client writes the answer.

## Learning And Evidence

Only the exact direct-user target supplies automatic fact testimony. Bounded preceding context may resolve references or time, but remains a revalidated dependency. Every reuse proves that target and dependencies still belong to the active DAG path and satisfy source, pause, exclusion, deletion and generation fences. Assistant speech can support history recall, never a user fact.

Explicit Saved Memory outranks automatic evidence. High-confidence durable observations may become current state; admitted lower-confidence propositions cannot supersede authoritative state or feed patterns. Authority-critical uncertainty fails closed. Exact evidence and immutable versions commit atomically and idempotently before optional embedding work. Repeated evidence has no semantic side effect; independent corroboration reinforces without inventing competing truth. Rejecting a candidate cannot remove an older safe current version.

Identity is server-owned, Unicode-preserving and independent of search folding, transliteration, category or provider labels. Missing identity dimensions are never guessed; weak identity remains a proposition. Named third parties do not become the user's self subject. Entities and aliases aid identity and retrieval, never confer semantic authority. Lexical similarity alone cannot merge entities; loss of exact source support fences reuse, and retracted roots are not revived. Current-pointer changes, merges and corrections require fresh exact targets and the bounded semantic adjudication authority; ambiguity becomes conflict. Retrospective state does not silently replace current state.

Safety Lite is local and independent from semantic classification. It redacts recognized exact secret spans before every Memory persistence, provider, index, context and debug boundary, preserving meaningful safe remainder. Generic high entropy is audit-only; ordinary personal, medical, financial or relationship text is not a secret class. Raw recognized secrets may remain only in the authoritative chat under its own contract. Reprojection rechecks owner/source/lifecycle authority and never revives purged or retracted rows. See [safetyLite.ts](../lib/server/memory/safetyLite.ts).

Expiration requires grounded source language and validated calendar interpretation. An unresolved explicit TTL rejects the candidate instead of making it permanent. Reads enforce expiration synchronously; cleanup is not authorization. Expiring or superseding a version never resurrects an older version.

Pattern discovery is enabled by default, forward-only from first enable, and lower-authority depth-one inference. A pattern needs at least three independently supported direct evidence roots; several facts from one message do not qualify. It cannot own hard current state, feed another pattern, or enter history/profile/aggregation authority. Selected patterns carry freshly rejoined direct supports and lose admission immediately when those supports fail. Disable stops synthesis without deleting valid patterns. Product qualification remains guarded until an explicitly authorized manual audit contains at least thirty non-empty live proposals, at least 95% precision and at most 5% unsupported generalization.

## Retrieval And Presentation

Search indexes are rebuildable candidate projections; PostgreSQL remains authority. Every hit rejoins current owner, source, safe-content hash, lifecycle, generation, suppression, deletion and expiration proof before fusion and again before freezing the pack. OpenSearch failure or rejected derived evidence falls back without weakening those fences. Script or language metadata never selects an analyzer or grants eligibility. Retrieval/index revisions are distinct from destructive content generations: reindexing cannot orphan valid semantic evidence.

Independent candidate lanes contribute ranks, not directly comparable raw scores. Optional lane failure preserves remaining evidence. A temporal interpretation may restrict only its dedicated lane and retains an unrestricted fallback. Current reads follow the exact current-version pointer; historical reads resolve canonical lineage without duplicating moved/merged representations or reviving forgotten, expired or conflicted versions. Source diversity is an ordering preference, not a quota.

A governed reranker scores safe candidates only. Any approved route fallback stays within the accepted route and deadline; scores from different models never mix. Incomplete or invalid coverage discards the whole score set and preserves fused ordering. A calibrated near-zero filter cannot remove exact-text or exact-alias anchors; a model without trustworthy calibration has no such floor. Useful-memory prioritization is enabled by default and affects ordering only: it cannot remove evidence, bypass fences, extend validity, or alter semantic lifecycle. Only versions in the frozen pack receive idempotent access touches, whose failure cannot fail the answer.

The reader receives bounded untrusted evidence with source/speaker authority, dates, currentness and derived status, surrounded by trusted reader instructions. Raw evidence outranks summaries for exact details; instructions inside evidence are ignored. Relevance selection precedes chronology, unrelated older material cannot displace salient evidence, and identical wording in distinct events is not deduplication proof. Current answers respect later state and request-specific exclusions; historical questions retain historical state. Counting deduplicates actual occurrences and requires grounded quantities, never a model-authored total. Optional planning failure leaves the source evidence available. Prompt wording and packing policies are owned by [retrieval](../lib/server/memory/retrieval/).

Digests and contextual keys navigate to raw supported excerpts; they do not grant relevance to an entire chat or become exact fact authority. Missing generated context falls back to safe raw material. History preserves roles, message boundaries, exact provenance and timestamps. Only an allowlisted, sanitized projection of settled tool observations may enter episodic recall; raw tool arguments/results never do. Neither digests, tool observations nor assistant text become automatic fact or pattern evidence.

Phase B freezes the exact authorized pack; recovery does not retrieve again. Browser sources derive only from committed run items and carry friendly text plus opaque operation-bound references, never repository identities, scores or internal policy. Every source action revalidates current authority; presentation grouping cannot authorize navigation or mutation. [Run contracts](RUN_CONTRACTS.md) owns admission and settlement.

## Cutover And Deletion

Forget, edit, exclusion, pause and reset advance synchronous fences before deferred cleanup, so old jobs, vectors or unchanged evidence cannot resurrect content. Deletion duties remain retryable and are never terminally abandoned. Provider capability failure disables only the affected stage, preserving ordinary answers and deletion work.

Semantic cutover requires an explicit operator disposition after aggregate-only inventory, including an explicit no-op for zero rows. Retained legacy rows remain excluded from new authority until safely disposed; cutover never upgrades them to direct evidence. Identity migration does not rewrite accepted keys: activation requires its collision preflight, ambiguity disables legacy reuse, and rollback retains exact write identity. See [semantic cutover](../lib/server/memory/operational/cutover.ts) and [identity cutover](../lib/server/memory/learning/identity/cutover.ts).

Retrieval cutover builds a compatible shadow generation, proves full coverage and required vectors, activates one pointer and retains exact rollback. It never replays semantic learning or tool side effects. History projection changes require valid checkpoint proof or bounded rebuilding, not relabeling old proof. Relaxing contextual source validation requires same-corpus retrieval evidence and explicitly authorized provider qualification; deterministic evidence alone is insufficient.

Backup requires writer quiescence and every suppression key referenced by durable state. Restore waits for deletion, barrier, execution and generation review. [Persistence](PERSISTENCE.md) owns those operations; [Security](SECURITY.md) owns credentials and egress.
