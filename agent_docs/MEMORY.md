# MEMORY

Owner: Native Memory maintainers
Scope: Personal Memory semantics, evidence, privacy, retrieval, learning, lifecycle, and recovery.

## Product Contract

For open-ended guidance, one optional strict System Model resolver may derive a bounded current-response-only keep/avoid/prefer interpretation from the sanitized current query and exact source-mapped direct-user spans. It may start early from the bounded original-query speculative retrieval frontier while Memory control is still running, but it attaches only when its governed result is already fully settled at the final pack boundary; Memory admission never waits there for resolver progress. A pending resolver is cancelled, its terminal governed settlement completes before retrieval-attempt acceptance, and the ordinary healthy pack continues unchanged. The speculative frontier grants no answer authority: the final plan, authoritative rejoin, pack, exact quotes, item identities, and surviving evidence handles must all validate before any constraint reaches the reader. The resolver cannot consume Assistant text, mutate durable Memory, remove or reorder evidence, or grant retrieval authority. Ambiguity, speculative/final drift, invalid output, timeout, unavailable consent/capability, or insufficient pack budget preserves the ordinary reader pack as healthy `USED` rather than manufacturing `DEGRADED`. The provider prompt sandwiches the untrusted Personal Context between the full trusted reader contract and a compact trusted finalization reminder; the latter contains no source text and reasserts query-local semantic constraints without another provider call.

Personal Memory is AIQSA-owned PostgreSQL state with five user controls: the master Memory switch, Search past chats, Learn automatically, opt-in pattern discovery, and opt-in useful-memory prioritization. Saved Memories remain directly manageable while Memory is paused; pausing a source stops new use and work without silently deleting retained data. Reset requires confirmation, fences future admission synchronously, and drains reusable Personal Memory through the durable deletion path.

Personal Memory has five reusable inputs: explicit Saved Memories, conservative direct-user learned facts, role-preserving personal past-chat evidence, bounded safe observations derived from settled tool executions, and independently safety-admitted pattern propositions. Folder, Assistant, arbitrary user-facing scopes, generated profiles, user-facing conflict workflows, and Project Memory are outside this product. Existing Project Memory data may remain dormant, but Project runs create and receive no Personal or Project Memory bindings, context, sources, or jobs.

Temporary chats create no Personal Memory attempt, binding, item, source, receipt, counter change, or background work. Anonymous shares retain only their positive public snapshot and strip all Memory context, actions, references, sources, and lifecycle metadata.

## Actions, Evidence, And Safety

Natural-language Memory actions are decided by one bounded forced-strict System Model call over a locally secret-redacted projection of the current direct-user message. The exact current message remains server-side evidence and is never replaced by that projection. The answer model receives no Memory tools. Supported outcomes are `NONE`, `SAVE`, `UPDATE`, `FORGET`, `LIST`, `SEARCH`, and `RESET`; at most one further strict call may resolve an ambiguous owned target, and destructive reset still requires explicit confirmation. Mutation authority requires a byte-for-byte retained projection rederived from the authoritative current user turn plus an exact current owned target where applicable. Missing, invalid, or timed-out control yields `NONE` and cannot infer or replay a mutation. Assistant text, retrieved Memory, earlier turns, quotations, Search, Knowledge, MCP, tools, and attachments cannot authorize a mutation or become evidence for a user fact.

Durability, category, subject, correction, and target decisions may belong to forced-strict System Model contracts, but Memory safety does not. Local `Memory Safety Lite v1` returns typed UTF-16 spans and redacts PEM private keys, credential URLs, valid JWTs, known token formats, recovery codes, and Luhn-valid payment-card candidates longest-span-first; generic high entropy is count-only and never changes redaction or eligibility. A mixed message, query, digest, or explicit mutation retains every meaningful safe source span, while a secret-only, empty, oversize, control-unsafe, or independently ineligible projection is fenced. The same last-line projection runs before Memory control, extraction, digest generation, embeddings, query embeddings, reranking, aggregation, answer context, indexing, and debug serialization. New fact versions store synchronous local policy outcomes with null semantic-classifier execution/provider/model fields; chunks apply the same policy synchronously without a classifier. Ordinary personal, medical, financial, preference, and relationship text is not a secret class. Raw recognized secrets may remain only in the authoritative Chat message under the Chat contract and never in a Memory derivative.

Automatic learning gives each eligible direct-user message one destructive-generation-bound deterministic extraction job after its committed Normal turn. Preparation reloads that immutable target plus a contiguous suffix of at most two immediately preceding safe user/assistant turn groups and current facts as opaque context refs; the complete message projection, including the target, is capped at six messages and 8,000 redacted characters. Only the exact current direct-user target can supply testimony or evidence. Prior user text and visible completed assistant text may resolve a reference, relation, correction, or temporal expression, but are retained only as revalidated dependencies; assistant text never attests a user fact. Later turns and branch changes that retain the target and every required dependency on the active message-DAG path do not invalidate it; a path that excludes one, source deletion or edit, exclusion, pause intervals, suppression, Project boundaries, and destructive generation changes still fail closed. One strict extraction may return zero to four independently validated observations with a language-neutral semantic frame and explicit zero-based exact-occurrence references; offsets use UTF-16 wire units and preserve source Unicode exactly. Every high-risk candidate class is resolved together by zero or one further forced-strict semantic adjudication call for that source. There is no later entity, ownership, temporal, or relation provider call. Durable, future-useful, allowlisted, storable `HIGH` observations may participate in authoritative current state. A narrowly admitted direct-user `MEDIUM` assertion is stored only as a lower-authority proposition unless bounded adjudication establishes it as fresh supporting evidence for an existing authoritative fact; it cannot become core, supersede or override authoritative state, or feed pattern synthesis. `LOW` and authority-critical uncertainty are rejected.

The automatic write path is append-only: a new proposition commits its fact, immutable version, exact evidence, and event atomically. New automatic evidence records the direct-user quote, UTF-16 offsets, source-content hash, projection version, and separately domain-versioned observation/evidence fingerprints. An exact normalized duplicate from another direct source attaches fresh evidence and reinforcement without creating a competing version. A plausible cross-key duplicate against supplied current direct-fact context requires bounded strict semantic adjudication; an unambiguous `REINFORCE` attaches the new evidence to that active explicit or automatic version, preserves explicit authority, and creates no second fact, while a stale or ambiguous target fails closed. Replay of the same evidence fingerprint has no semantic side effect. Stored branch generation is observation-time audit, while current reuse re-proves message membership in the active DAG path. Explicit Saved Memory retains higher authority. Semantic persistence does not wait for embeddings: compatible indexing is queued independently and remains retryable after the fact commit.

Automatic identity is server-owned and versioned. An allowlisted dimension-bearing `SLOT` represents one mutable subject/predicate/dimension truth; weak or unsupported identity falls back to a normalized `PROPOSITION`. Unicode identity-component v2 emits a readable token only when the complete NFKC, locale-independent case-normalized value is an ASCII-safe component; every other value, including punctuation-bearing ASCII, hashes the complete normalized input. It never consumes search folding, transliteration, n-grams, script inference, or a language-specific character substitution. Component-backed facts use `slot:v4`, ordinary and supporting propositions use the separately versioned `prop:v2`, and grounded entities use `entity:v4`; entity-root product facts remain profile-independent `slot:v3`. A direct relationship observation about a named third party is a proposition whose exact mention may bind an owner-scoped `PERSON` entity as provenance, never the user's self subject. Category never participates in identity, required dimensions are never guessed, and the single product-status vocabulary keeps considering, ordered, owned, borrowed, shared, and work-device states distinct.

Identity migration never rewrites an accepted fact/entity key. Every extraction job captures one `LEGACY_V1` or `UNICODE_V2` write profile in its idempotency identity, while the repository derives both keys and prefers an existing Unicode row before a proven-unambiguous legacy row. A compatibility ledger persists only owner/container-scoped SHA-256 key pairs and bounded counters; one legacy hash mapped to several Unicode hashes disables legacy reuse. Aggregate inventory, bounded source-job reconciliation and activation preflight expose no key, label, statement, alias, email, or owner identifier. `UNICODE_V2` activation is explicit after that preflight; `LEGACY_V1` remains an exact write rollback, and both modes continue dual-reading the other namespace. Derived synthesis patterns use their own source-set identity rather than normalized proposition text; synthesis dual-reads its versioned `prop:v1`/`prop:v2` pair and those rows do not enter the proposition-normalization collision inventory.

Entities are owner-scoped identity and retrieval aids, not provider semantic authority. Product-status SLOT identity is `slot:v3` anchored to the canonical `subjectEntityId` root; `PRODUCT` and `DEVICE` are one compatible family, while provider label, brand, and model never enter the durable fact key. Resolution is conservative: an exact supplied context root precedes a server key or exact supported alias, creation requires an exact named/nominal source span, broad/specific lexical similarity never merges entities, and only a bounded `ENTAILED`/`HIGH` exact-alias collision may invoke the idempotent merge path. One source-valid alias-support authority governs context, resolution, relations, synthesis, rebuild, and retrieval; pronouns are never aliases, final support loss fences reuse synchronously, and an automatic-only zero-support root may become terminally `RETRACTED`. Historical merge links remain immutable, merged children never promote themselves, and a fresh exact observation creates a new root rather than resolving a retracted one.

Semantic lifecycle and Safety Lite admission are independent. A new automatic version receives its synchronous local classification in the semantic commit and does not wait for a safety provider; legacy `PENDING`, `UNCERTAIN`, or surviving content-bearing `SECRET_FENCED` rows are handled only by bounded owner/source/lifecycle-authorized reprojection. Purged or retracted legacy rows are never revived. Same identity/value evidence reinforces the immutable canonical version; a different value for the same slot is a non-current relation-pending version. Candidate rejection terminalizes only that candidate and cannot remove an older safe current.

Relation resolution consumes only the stored semantic frame, the source-batched adjudication, code-owned values, opaque refs, and a fresh locked snapshot. A compatible representation merges into one canonical truth without inventing history; a genuine allowed state change or explicit correction supersedes and preserves the prior state. Pointer changes, cross-fact moves, and entity/representation merges require a fresh valid target plus `ENTAILED` and `HIGH` adjudication authority. Explicit current Memory outranks conflicting automatic evidence, retrospective states do not silently replace the present, and missing, stale, or ambiguous authority becomes a durable conflict without another provider call.

Reuse expiration is set only from an exact referenced expression plus a validated language-independent calendar operation and remains independent from domain validity. Invalid optional temporal metadata degrades to null; an explicit TTL that cannot resolve safely rejects that candidate rather than storing it indefinitely. Ordinary reads, action/source projections, rebuilds, and embedding rejoins synchronously require an absent or future `expiresAt`; background cleanup is not an admission boundary. A write under the same identity first materializes any due current version as expired, clears its reusable pointer/index, and never resurrects an older superseded version.

Pattern discovery is off by default, forward-only from its first-enable boundary, and independent of ordinary chat and direct Memory. A bounded scheduled strict call may derive only lower-authority depth-one proposition patterns from at least three distinct currently eligible direct versions backed by at least three independent direct evidence roots inside one conservative entity/semantic/time cluster; several facts extracted from one message never satisfy that threshold. Ordinary scheduling requires a changed eligible source set, thirty minutes without new evidence, and either eight new evidence-bearing chats, twelve changed direct facts, or a twenty-four-hour low-activity fallback; a twelve-hour hard cooldown limits ordinary provider frequency but never acts as a timer by itself. Provider inputs use only call-local opaque entity handles resolved against frozen server-side bindings, never repository entity IDs. Every PATTERN retains its per-pattern ingestion identity, exact source-set identity, succeeded execution receipt, immutable `SYNTHESIZED_FROM` relations, and synchronous Safety Lite admission. It never owns hard SLOT state and is demoted below direct Memory. Disable stops new synthesis without moving the boundary or deleting valid patterns. One reusable-fact authority contract governs direct and evidence-less PATTERN admission through incremental and full indexing, embeddings, retrieval, selected-item rejoin, and frozen packing. Server policy automatically exposes that lower-authority candidate tier only to targeted-current fact retrieval; the System Model reports an explicit semantic user opt-out but never grants PATTERN authority, and no language-specific keyword parser controls admission. Profiles, historical states, aggregation, and past-chat modes remain closed. Source, dependency, lifecycle, expiration, or destructive content-generation loss fails authoritative rejoin immediately. A selected PATTERN is explicitly derived and reaches the reader only with a bounded set of at least three freshly rejoined, independent direct supports; newer contradictory direct Memory has higher authority, and a PATTERN without those supports is omitted. Search-index cutover advances the retrieval revision and active-index pointer but not that destructive content generation, so reindexing cannot orphan an otherwise valid PATTERN. Bounded reconciliation retracts invalid patterns immediately and may schedule one cooldown-bypassing targeted replacement only when at least three exact independent direct roots remain, preserving direct memories and audit lineage. The fixed EN/RU/mixed deterministic qualification covers the required positive, adversarial, mutation, deletion, depth, tenant, and context cases; product qualification remains guarded until an explicitly authorized manual audit contains at least thirty non-empty live proposals at 95% precision or better and no more than 5% unsupported generalization.

Facts and versions remain immutable evidence records. Active v1 Personal facts are user-global; legacy non-global and Project records are not broadened or destructively migrated. Forget/edit/reset synchronously advances the applicable fences before deferred derivative cleanup, so queued jobs, rebuilds, stale vectors, or unchanged evidence cannot resurrect content.

## Retrieval And Run Admission

Each eligible Normal send/regeneration uses the run's two-phase boundary. Phase A accepts a private non-dispatchable run and one content-bounded retrieval attempt before optional Memory utility calls. Every non-empty ordinary answer begins with a deterministic local plan over the bounded `originalSanitizedQuery`; enabled facts and past chats remain eligible even when control is missing or says Memory is not useful. A valid strict System Model decision may narrow a deliberate profile, historical, past-chat, aggregation, or response-preference route and may add a semantic rewrite, but that rewrite supplements rather than replaces the original. For a genuinely multi-part request it may additionally supply at most two standalone facet or boundary subqueries; these supplement both the original and rewrite, never encode the final comparison or calculation, and remain absent for a single-facet lookup. The query bundle is deterministically deduplicated and bounded to four semantic and two temporal variants. Control failure or an invalid enriched plan preserves mutation `NONE`, records a content-free fallback reason, and runs the broad deterministic plan. Its past-chat evidence remains lossless and chronological so the reader can derive current, historical, as-of, event, or aggregation semantics from the current user request without optional classification. A complete authoritative local pack remains healthy `USED`; only material candidate/evidence coverage loss becomes `DEGRADED`. A valid pure explicit action remains the only route that skips ordinary read retrieval. Entity hints are limited to eight exact query occurrences with owner-validated opaque refs and grant no fact, source, lifecycle, safety, or mutation authority; patterns default off and are available only to targeted-current retrieval.
Exact fact text, supported entity aliases, lexical search, vectors, recent/temporal signals, and targeted digest navigation are independent candidate signals: an unavailable signal is recorded and the remaining signals continue. `MemorySearchEntry` lexical discovery crosses one bounded provider contract carrying normalized variants and authority scope in and only entry IDs, safe-content hashes, variant ranks, and content-free evidence out. The PostgreSQL rollback path uses the generic `UNICODE_ICU_NGRAM_V1` compatibility profile for every query: NFKC plus locale-independent case normalization preserves character distinctions, a `simple` Unicode projection is primary, and bounded matching against the raw normalized projection is the lower-weight n-gram fallback. A separately versioned OpenSearch projection is populated and integrity-audited asynchronously. Its compatibility version is owned only by the lexical document/query contract; reader, packer, resolver, and admission revisions do not invalidate an otherwise identical projection. In `SHADOW`, it runs under a process-wide no-queue concurrency cap and strict detached deadline; PostgreSQL output and health remain authoritative, and only content-free parity/freshness evidence is emitted. `OPENSEARCH_CANARY` chooses a stable user cohort from the already HMAC-derived routing scope, while `OPENSEARCH` selects OpenSearch for every user. Both modes fall back to the generic PostgreSQL provider when projection readiness, transport, response validation, canonical guard, or the bounded Memory-only circuit breaker rejects OpenSearch. One half-open probe is admitted after cooldown; Knowledge owns no state in that breaker. OpenSearch fallback analysis is decided after candidates pass the existing PostgreSQL canonical selectors, so a stale raw hit cannot suppress transliteration/n-gram recovery; an all-rejected caught-up candidate set instead retries the same lexical lane through PostgreSQL and records the closed guard code. Script, declared language and BCP-47 metadata never select a lane or analyzer. English/Russian vectors and Russian transliteration remain only inside the isolated legacy shadow/rollback adapter until their retention window ends. The Memory repository always rejoins provider identities through its existing PostgreSQL fact/history selectors before fusion; provider output cannot authorize, expand, rerank, pack, or enter the prompt directly. Digest search remains a separate PostgreSQL navigation path. Weighted rank-only RRF groups duplicate projections by their source-bound evidence root, and source diversity changes bounded ordering without imposing a per-source quota. Missing, partial, invalid, timed-out, or unavailable query embedding preserves local lexical/entity/temporal/recent lanes. Ordinary aggregation is reader-first: it retains the complete bounded raw evidence pack, may add only server-proven source-bound deterministic guidance, and makes no aggregation-provider call.

Every synchronous Memory database read class has a transaction-local statement/lock budget shorter than its application settle window; the settle window bounds response latency while the database budget bounds detached work, and synchronous reads are not retried after timeout. An optional lexical timeout degrades only that lane. Provider-neutral lexical diagnostics contain only bounded backend/lane/match mode, timing, raw/canonical and authority-rejection counts, readiness/lag, fallback, opaque-request presence, overlap ratios, and failure fields—never query, document, fact, title, owner, or opaque entry identity—and remain outside the model prompt. An issued retrieval snapshot is a runtime-frozen exact-instance capability with complete private authority identity. History availability uses bounded revision/source authority rather than enumerating suppressions, barriers, or pause intervals; every canonical read still rechecks current settings, source proof, barriers, suppressions, and expiration time.

The independently selected score-only reranker receives dated, speaker/source-attributed, current-or-historical safe candidates after authoritative filtering and cannot make authority decisions. An approved administrator selection resolves to one versioned ordered route. A typed retryable availability failure discards the complete logical result and reruns every batch on the next route model inside the same deadline; scores from different models are never mixed or compared. Successful model fallback is operational evidence, not Memory degradation, while exhausting the route preserves the complete fused RRF order. Semantic scores apply only when every batch from one model has the same governed snapshot and exact one-to-one coverage of the complete candidate pool. A complete score set may reject only candidates below that exact model's conservative versioned near-zero junk floor; a model without trustworthy calibration has no floor. Exact-text and exact-alias anchors remain admissible, as does a profile anchor when the profile was explicitly requested. Any missing, duplicate, unknown, invalid, failed, cancelled, or snapshot-mismatched result disables the floor, discards every semantic score, and preserves the full fused RRF order, including episodic history. With no usable candidate signal, dynamic Memory is empty and the ordinary answer remains available.

A bounded local EN/RU temporal parser anchors relative expressions to the accepted run timestamp in the accepted request zone, or the recorded UTC fallback when no request zone exists. A high-confidence interval may hard-filter only its dedicated temporal lane; a lower-confidence match changes ordering only, and every matched temporal query also executes a time-unrestricted fallback lane. Ambiguous, invalid, or absent interpretation cannot suppress ordinary retrieval, and temporal diagnostics expose only parser state/type/confidence and candidate counts. Reliable relative dates in fact extraction and chat digests retain their original wording/source time while adding the grounded absolute date; no stage invents an unsupported event time.

The plan names one closed mode: current profile, targeted current facts, historical fact memory, past-chat search, or history overview, together with a compatible current, historical, as-of, between, or any-time intent. Current fact retrieval follows the fact's exact ACTIVE current-version pointer. Historical retrieval resolves every bounded `movedToFactId` chain to one owner-scoped ACTIVE canonical root and deduplicates by that root plus structured semantic value and domain-time identity. It may return the canonical current version plus each genuine SUPERSEDED state once, but never MERGED, duplicate moved representations, EXPIRED, forgotten, conflicted, broken-chain, or unrelated versions. Exact, FTS, vector, digest-navigation, recent, temporal, and entity lanes contribute only ranks to versioned weighted reciprocal-rank fusion; raw scores from unlike lanes are never compared. Entity, currentness, lifecycle, source, generation, deletion, and temporal admission remain server-owned fences; model outputs can only influence ordering.

The administrator owns one installation-wide admission timeout for future Personal Memory attempts. It defaults to 30 seconds and is bounded to 1–120 seconds. Each optional control, query-embedding, sorter, and aggregation call receives a bounded child budget that reserves time for deterministic local retrieval and packing; a child timeout degrades only that signal. Exhaustion of the outer deadline still cancels remaining work and continues the ordinary answer without Memory rather than failing the chat run.

Outside the bounded broad current-fact inventory, the only query-independent context is a small set of explicit, current, user-global response preferences. The reader pack selects one adaptive target/hard-cap profile: simple/current facts use 6k/10k tokens, targeted past-chat reads use 10k/16k, and multi-source, aggregation, history-overview, recency, or complex temporal reads use 24k/32k. These are maxima rather than fill targets and are always clamped to the admitted provider context envelope. Per-class, source, and item ceilings remain independently bounded.

After relevance selection, the internal untrusted JSONL evidence block uses only opaque evidence/session handles and explicit type, speaker/source authority, ISO-or-unknown document/event/observation/validity time, currentness, safe raw text, retrieval reason, and derived state; it never serializes repository identities. Normally, evidence from one selected fact lineage or source session is rendered old to new inside its existing relevance slots and unrelated evidence is not globally date-sorted. For a non-aggregation answer, the sanitized planner rewrite may additionally appear as a non-evidentiary answer focus that restates only the requested subject, predicate, relation, or attribute; it never supplies an answer or overrides the current user message. A trusted `state_resolution=latest_exact_slot` header is minted only for structured current-state past-chat intent; an ordinary past event, current atomic-fact read, or profile receives no raw-timeline state-reduction instruction. That current-slot path retains every admitted item but renders undated evidence first and the complete dated raw timeline old to new across source sessions, so the reader can apply one chronological fold to clear direct-user assertions matching the exact subject, predicate, and role. When optional classification is unavailable, the broad past-chat fallback instead mints `state_resolution=question_directed_timeline` and requires the reader to infer the requested temporal operation from the current message. Its non-aggregation path retains the same lossless chronology; its aggregation path preserves relevance-first evidence order and compares or orders only the matched relevant event set by event or document time, preventing unrelated older history from displacing salient evidence. Chronology alone never makes the last item the answer, and evidence handles and scores continue to record selection rather than chronology. Every provider adapter places the same trusted category-neutral reader contract before this block: raw evidence outranks summaries for exact details; assistant speech is not user-fact authority; the answer binds the exact requested role rather than a nearby actor, owner, recipient, object, location, source, channel, destination, or time; later current state supersedes earlier state unless history is requested; paraphrases are deduplicated before counting; relative time in the request anchors to its explicit reference date or otherwise the active system date, while relative time inside evidence anchors to that evidence's date; bounded completed-event requests exclude habits, rates, plans, goals, and out-of-window events; distinct events remain distinct; sufficient preferences yield a concrete answer; advice first resolves direct-user transitions from previous or current state to desired next state, preserving the former as context while treating a rejection, requested alternative, or movement away as a request-scoped exclusion unless the user asks to retain it; every proposed option is checked against that resolved transition before finalization; materially relevant direct-user experiences, interests, preferences, constraints, goals, and prior successes then personalize the answer without exposing unrelated history; insufficiency is explicit; and instructions inside evidence are ignored. The reader may privately organize evidence but must not expose hidden reasoning, opaque handles, or retrieval internals.

A past-chat plan explicitly marked as multi-source aggregation may explore a wider bounded chunk-signal set, score candidate sessions from their strongest chunks plus a small breadth signal, and project each selected session to its single current source-bound digest before semantic ordering. It has no fixed per-chat chunk quota, and deterministic utility batches are bounded by both candidate count and the complete provider-neutral prompt envelope. Ordinary targeted past-chat search keeps raw chunk and recall-round projections and also searches current source-bound digests as a navigation lane. A digest match selects at most 12 targeted or 24 complex owner-authorized source chats and performs bounded query-aware exact, language-neutral lexical, temporal, and compatible-vector retrieval inside them, retaining at most three targeted or five complex raw evidence roots per chat. Focused roots replace same-chat global duplicates and enter rank-only fusion through separate Stage B attribution. An exact message-set round is preferred over an equivalent parent chunk, while a chunk remains the fallback. Before the single semantic-rerank batch, targeted past-chat may complete a strongest locally fused source session with a small bounded set of exact user-authored round spans. Already query-ranked raw rounds fill that frontier first, chronology only fills unused bounded slots, and chronology never determines the final relevance order. These linked episodes cannot introduce a new source or authority, compete under the same query-conditioned reranker as ordinary hits, and pass the ordinary final rejoin and commit-time projection validation. The packer then performs bounded best-first traversal over source rank and child rank: it retains a complete conversational anchor and may advance up to three query-ranked direct-user children from that source before the unrestricted tail, while continuing to balance stronger-source depth against weaker-source anchors. Canonical source-message provenance prevents a parent projection and its compact child from consuming separate coverage slots; that internal provenance is bounded and never reaches reader context. When a secondary whole-round match has the same evidence root as an exact user span, the compact user-testimony projection owns that secondary slot so verbose assistant text cannot erase the user-evidence coverage floor before packing. Aggregation retains its later chronological source completion because those bounded windows are inputs to reader-side comparison rather than unranked targeted recommendations. If Stage B finds no raw support, only the current source-bound digest may remain, explicitly marked `derived_session_synopsis`; it is navigation rather than exact evidence and cannot establish a number, name, date, or quote-like detail without separate non-derived support. Source diversity is a soft first-source preference rather than an exclusion rule. Every selected item is authoritatively rejoined under owner, canonical fact root, lifecycle/current pointer, expiration, exact evidence hash/offset, source dependency, entity-root, safety classification, source projection/revision, exclusion, suppression, and deletion fences; candidates produced from an index additionally require its exact compatible active generation, while direct exact/profile/entity candidates rejoin the underlying fact version without inventing an index dependency. A ranking-signal or sorter failure may yield a visible `DEGRADED` pack with RRF-ordered evidence, but failure of any mandatory fence removes the affected item or fails the pack closed. Phase B freezes the exact untrusted pack and validated planner hints; recovery reuses it and never retrieves again.

A non-empty explicit aggregation pack receives one further bounded global strict evidence plan over only that already safe, rejoined pack. The plan groups exact-evidence-grounded occurrences as set members, temporal or relational boundaries, support, or exclusions. For a count, an individually identified member contributes one while an explicit aggregate cardinality contributes only its exact evidence-grounded positive integer; application code sums those quantities and never accepts a model-authored total. Separate category totals that the query explicitly asks to combine remain additive unless supplied evidence identifies an actual overlap. A map shard exposes only whether its grounded group is applicable or contains a concrete conflict; shard scope is never presented to the complete reducer as semantic `PARTIAL`, and only that reducer assigns the final resolution after server-owned proof that every bounded shard was processed. Unavailable or unresolved planning degrades without hiding the underlying source evidence. This production path is question-semantic rather than benchmark-category-aware and receives no reference answer or expected count.

Useful-memory prioritization is off by default and changes search-time ordering only. Its versioned multiplier stays within `[0.3, 1.5]`, applies only after authoritative rejoin and optional semantic ordering to candidates that already passed every hard fence, never introduces a relevance threshold or removes an item, gives explicit or pinned current SLOT state a neutral floor, and dampens recency less for an explicit historical request. Turning it off immediately restores the pre-decay order while retaining only bounded use state. Only fact versions that enter the durable frozen pack receive one idempotent access touch for that binding; lane candidates, RRF/reranker-only rows, rejected rejoins, and past-chat chunks are never touched. Touch failure cannot fail the answer, change semantic lifecycle, or extend validity/expiration.

Only exact committed run items may produce browser Memory sources. The source contract receives friendly text and short-lived opaque owner/run/version/operation-bound references, never Memory repository IDs, hashes, scores, provider details, policy versions, revisions, or reasoning. Correct, Forget, Not relevant, and Open source revalidate the current authoritative item before acting; forgotten, excluded, deleted, stale, or non-current evidence cannot be replayed. Successful Open source may then redirect to the app's ordinary authenticated chat route. Public-share projection removes the entire private surface.

## History, Lifecycle, And Operations

Past-chat history preserves canonical `User:` and `Assistant:` labels, message boundaries, exact source maps, timestamps, and versioned source projections. Parent chunks remain a fallback search unit; a recall round is one paired turn or standalone visible message with an exact message-set evidence root and parent link. Long rounds are searched through versioned, bounded, overlapping child segments whose raw UTF-16 ranges and message intersections rejoin the exact parent text; generation cutover may retain legacy round search only as an explicit rollback/fallback, and overlapping hits still count as one parent evidence root. Its one contextual narrative key may use at most two prior groups, is generated in bounded chat batches, and always retains the raw round for exact terms; unsupported, invalid, or unavailable output falls back to that raw key without blocking indexing. Contextual output declares a structurally validated BCP-47 language tag, or `mixed`/`und`, without inferring a language from script or limiting supported languages to reporting buckets. Every attempted fallback has one or more closed, content-free reason codes, and language qualification aggregates use `en`, `ru`, `mixed`, `und`, and `other` only as metrics dimensions. The strict source-bound validator remains the production boundary until same-corpus retrieval and explicitly authorized provider qualification justify a narrower controlled equivalence; deterministic evidence alone cannot enable relaxation. Contextual keys are search projections, never evidence: every generated form retains its exact cited prior-round dependencies, and rerank/reader handoff pairs the explicitly non-authoritative hint with the matched raw span plus only those bounded raw supports. A missing, stale, unsafe, unauthorized, or generation-incompatible dependency strips the generated form to raw-only behavior rather than dropping the raw hit. Raw tool arguments/results remain private and outside the visible Chat DAG and Personal Memory derivatives. A separate versioned `TOOL_EVENT` projection may retain only deterministic allowlisted, bounded, Safety-Lite-projected fields from an owner-scoped settled call on a completed run with a known outcome. It participates only in episodic/history exact, lexical, vector, and temporal recall and reaches reranker/reader as lower-authority `tool_observation` evidence with tool name, outcome, occurrence time, and safe text. It never enters direct/current user facts, profile inventory, response preferences, automatic learning, or PATTERN synthesis. Assistant text may support past-chat recall but never automatic fact evidence. History applies Safety Lite locally before reusable persistence; System Model availability is relevant only to optional contextual keys and digests, never to raw lexical or tool-observation admission. Source reads are personal-only and exclude Temporary, Project, deleted, excluded, pre-cutoff, stale-branch, stale-revision, corrected-call, and incompatible-generation data.

History indexing reads the checkpoint and active-path metadata before message content. It reuses a chunk or round only while its ordered message identities, projected safe content, edit snapshots, admission, parent/source proof, and projection versions remain exact. A normal append loads and projects only a bounded contextual overlap plus the changed tail; branch or edit divergence rewinds to a bounded affected suffix, while invalid checkpoint proof, a pipeline change, or a source-context transition that invalidated reusable projections requires a bounded full rebuild. Such a transition records an explicit rebuild-required checkpoint marker instead of relabeling old proof as the current pipeline. Round configuration is generation-bound: a complete compatible shadow generation activates through one pointer only after every eligible retained chat has a current-pipeline checkpoint, retains the exact prior generation for rollback, and keeps chunks alongside rounds during the compatibility generation. Content-free work counters make those bounds verifiable without wall-clock claims. Tool-event backfill and rebuild read existing settled records only and never replay an external call; exact source-call update time, run/call settlement, owner, branch/revision, exclusion, deletion, and active-generation joins fence every index, vector, rejoin, and frozen-item use. A corrected result creates a new content-derived projection while the old projection is immediately unusable and then invalidated; run/chat deletion cascades or invalidates all derivatives. Each eligible retained chat may have one current digest whose exact source maps cover the complete bounded eligible chunk/message sequence. Within its bound, the digest preserves distinct concrete user-authored episodes and autobiographical details even when they are incidental to the chat's main request, prioritizing those attributable details over generic assistant exposition. The digest advances from its previously Safety-Lite-projected derived text plus a bounded exact delta, skips generation when the coverage fingerprint is unchanged, and periodically or after divergence performs a policy-versioned bounded hierarchical rebuild over early and late history. Digest unavailability or invalid output commits the safe raw projections with a content-free degraded reason instead of failing their indexing. Ordinary targeted past-chat search admits attributable chunks and rounds through exact, lexical, compatible vector, and digest-navigation signals; a digest hit must run owner-scoped raw retrieval inside its current source chat before either packing raw support or retaining only the explicitly derived synopsis fallback. Explicit multi-source aggregation uses bounded raw signals only to select sessions, then admits each session's current attributable digest; an explicit broad history overview also admits source-bound digests across chats. Neither chunks, rounds, contextual keys, prior digests, current digests, nor tool observations become automatic fact evidence, synthesized profile authority, or another source of hard facts.

Archive is organization only. Exclude immediately fences the retained chat as a future recall and learning source, but does not disable Personal Memory retrieval into that chat; Temporary and Project chats remain fully outside Personal Memory. Resume affects only messages created after its server-owned cutoff; it never schedules automatic historical backfill. Master/subordinate OFF periods and reset use durable generation, revision, cutoff, cancellation, and source barriers so delayed workers cannot commit old evidence.

One production Memory worker owns a complete declared job manifest, bounded leases, heartbeats, retry policy, and visible terminalization of unsupported legacy kinds. Startup verifies schema/write authority, registry completeness, key material, every actually admitted System/embedding credential envelope, and a rollback-only claim/heartbeat/commit transition without provider network I/O. Provider capability failures disable only the affected Memory stage; they do not prevent ordinary answers or unrelated deletion work.

Semantic deployment cutover is an explicit operator gate. Its inventory reads aggregate counts only and never projects Memory content, aliases, entity labels, provider bodies, prompts, emails, or raw owner identifiers. A zero inventory requires an explicit no-op disposition; retained nonzero rows require an explicit safe disposition and remain excluded from exact-vNext context, indexing, embedding, retrieval, rejoin, and frozen packs. Cutover never upgrades legacy rows to direct authority.

Retrieval-version cutover inventories only owner-scoped content hashes and identity snapshots, admits an idempotent shadow rebuild, activates exactly one compatible generation after full-set and mandatory-vector proof, and retains superseded generation entries for an exact-set rollback. It never replays source content or dual-writes semantic observations. Current source settlement produces only the vNext extraction path; unfinished legacy candidate consolidation/verification work is terminalized and those kinds are absent from the active worker manifest.

Deletion duties are retryable and never terminally abandoned. Backup requires writer quiescence and every suppression key referenced by durable state; restore remains blocked until deletion, barrier, execution, and generation review is clean.
