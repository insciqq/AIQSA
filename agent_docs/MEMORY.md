# MEMORY

Owner: Native Memory maintainers
Scope: Personal Memory semantics, evidence, privacy, retrieval, learning, lifecycle, and recovery.

## Product Contract

Personal Memory is AIQSA-owned PostgreSQL state with five user controls: the master Memory switch, Search past chats, Learn automatically, opt-in pattern discovery, and opt-in useful-memory prioritization. Saved Memories remain directly manageable while Memory is paused; pausing a source stops new use and work without silently deleting retained data. Reset requires confirmation, fences future admission synchronously, and drains reusable Personal Memory through the durable deletion path.

Personal Memory has four reusable inputs: explicit Saved Memories, conservative direct-user learned facts, role-preserving personal past-chat chunks, and independently safety-admitted pattern propositions. Folder, Assistant, arbitrary user-facing scopes, generated profiles, user-facing conflict workflows, and Project Memory are outside this product. Existing Project Memory data may remain dormant, but Project runs create and receive no Personal or Project Memory bindings, context, sources, or jobs.

Temporary chats create no Personal Memory attempt, binding, item, source, receipt, counter change, or background work. Anonymous shares retain only their positive public snapshot and strip all Memory context, actions, references, sources, and lifecycle metadata.

## Actions, Evidence, And Safety

Natural-language Memory actions are decided by one bounded forced-strict System Model call over the exact current direct-user message. The answer model receives no Memory tools. Supported outcomes are `NONE`, `SAVE`, `UPDATE`, `FORGET`, `LIST`, `SEARCH`, and `RESET`; at most one further strict call may resolve an ambiguous owned target, and destructive reset still requires explicit confirmation. Mutation authority requires byte-for-byte evidence from the current user turn plus an exact current owned target where applicable. Assistant text, retrieved Memory, earlier turns, quotations, Search, Knowledge, MCP, tools, and attachments cannot authorize a mutation or become evidence for a user fact.

Semantic safety, durability, category, subject, correction, and target decisions belong to forced-strict System Model contracts. A separate format-aware parser rejects recognizable credential URLs, keys/tokens, JWTs, PEM material, recovery codes, payment-card numbers, and high-entropy secret shapes before persistence or provider egress; regexes, keyword lists, locale phrase maps, and numeric heuristics are not semantic authority. Storable personal facts follow the ordinary persistence and retrieval rules; there is no separate Sensitive product mode. `SECRET` and `UNCERTAIN` content is never retained or recalled.

Automatic learning gives each eligible direct-user message one destructive-generation-bound deterministic extraction job after its committed Normal turn. Preparation reloads that immutable target plus a bounded set of owner-scoped, eligible prior direct-user messages and current facts as opaque context refs. Context never replaces the target's exact evidence: a coreference, correction, temporal, or relation-dependent observation commits immutable source-dependency provenance in the same semantic transaction and every read revalidates its bounded dependency chain. Assistant messages are never dependency authority. Later turns, assistant regeneration, and branch changes that retain the target on the active message-DAG path do not invalidate it; a path that excludes the target, source deletion or edit, exclusion, pause intervals, suppression, Project boundaries, and destructive generation changes still fail closed. One strict extraction may return zero to four independently validated observations, each with an exact target-user quote that the server re-locates and hashes. Only durable, future-useful, allowlisted, `HIGH`-confidence, storable, non-temporary, non-third-party observations proceed.

The automatic write path is append-only: a new proposition commits its fact, immutable version, exact evidence, and event atomically. New automatic evidence records the direct-user quote, UTF-16 offsets, source-content hash, projection version, and separately domain-versioned observation/evidence fingerprints. An exact normalized duplicate from another direct source attaches fresh evidence and reinforcement without creating a competing version; replay of the same evidence fingerprint has no semantic side effect. Stored branch generation is observation-time audit, while current reuse re-proves message membership in the active DAG path. Explicit Saved Memory retains higher authority. Semantic persistence does not wait for embeddings: compatible indexing is queued independently and remains retryable after the fact commit.

Automatic identity is server-owned and versioned. An allowlisted dimension-bearing `SLOT` represents one mutable subject/predicate/dimension truth; weak or unsupported identity falls back to a normalized `PROPOSITION`. Category never participates in identity, required dimensions are never guessed, and the single product-status vocabulary keeps considering, ordered, owned, borrowed, shared, and work-device states distinct.

Entities are owner-scoped retrieval aids, not semantic authority. Resolution is deterministic and conservative: an exact supplied context entity precedes an exact canonical key or supported alias, ambiguity creates no automatic merge, and product qualifiers prevent broad/specific collapse. Every automatic alias has evidence support, pronouns are never aliases, merges retain historical links while new reads/writes resolve the active root, and the entity retrieval lane reapplies the ordinary source, dependency, safety, lifecycle, scope, and expiration fences without requiring entity embeddings.

Semantic lifecycle and safety classification are independent. A new automatic version is safety-pending and cannot be indexed, embedded, retrieved, or replace an older reusable current until the independent classifier admits it. Same identity/value evidence reinforces the immutable canonical version; a different value for the same slot is a non-current relation-pending version. Rejection terminalizes only the rejected candidate and cannot remove an older safe current.

Relation resolution is deterministic first. A compatible representation merges into one canonical truth without inventing history; a genuine allowed state change or explicit correction supersedes and preserves the prior state. Explicit current Memory outranks conflicting automatic evidence, retrospective states do not silently replace the present, and unsupported ambiguity becomes a durable conflict. Only representation ambiguity may use the one optional strict auxiliary call shared by all Memory interpretation for that source message; a durable reservation prevents replay after an unknown or completed provider outcome.

Reuse expiration is set only from an exact resolvable TTL expression and remains independent from domain validity. Ordinary reads, action/source projections, rebuilds, and embedding rejoins synchronously require an absent or future `expiresAt`; background cleanup is not an admission boundary. A write under the same identity first materializes any due current version as expired, clears its reusable pointer/index, and never resurrects an older superseded version.

Pattern discovery is off by default, forward-only from its first-enable boundary, and independent of ordinary chat and direct Memory. A bounded scheduled strict call may derive only lower-authority depth-one proposition patterns from at least three distinct currently eligible direct versions inside one conservative entity/semantic/time cluster; twenty eligible versions are required before scheduling. Every PATTERN retains its per-pattern ingestion identity, exact source-set identity, succeeded execution receipt, and immutable `SYNTHESIZED_FROM` relations. It is non-retrievable until independently classified, never owns hard SLOT state, and is demoted below direct Memory. Disable stops new synthesis without moving the boundary or deleting valid patterns. Source, dependency, lifecycle, expiration, or generation loss fails authoritative rejoin immediately; bounded reconciliation retracts or replaces derived state while preserving direct memories and audit lineage.

Facts and versions remain immutable evidence records. Active v1 Personal facts are user-global; legacy non-global and Project records are not broadened or destructively migrated. Forget/edit/reset synchronously advances the applicable fences before deferred derivative cleanup, so queued jobs, rebuilds, stale vectors, or unchanged evidence cannot resurrect content.

## Retrieval And Run Admission

Each eligible Normal send/regeneration uses the run's two-phase boundary. Phase A accepts a private non-dispatchable run and one content-bounded retrieval attempt before optional Memory utility calls. A strict System Model plan decides independently whether facts, past chats, and response preferences are useful and supplies the bounded query text. Targeted dynamic Memory requires the plan, query embedding/index, configured candidate floors, and a forced-strict reranker over every candidate; lexical-only, vector-only, recent-only, or Core-only fallback is not allowed. For an explicit broad request for what Memory knows about the user, the same plan may instead authorize a bounded current-fact inventory: this lane excludes past-chat chunks, skips query embedding because there is no semantic subset to search for, and still requires the forced-strict reranker to accept every supplied current fact. Any missing or invalid required stage yields zero dynamic Memory items while the ordinary answer remains available.

The plan names one closed mode: current profile, targeted current facts, historical fact memory, past-chat search, or history overview, together with a compatible current, historical, as-of, between, or any-time intent. Current fact retrieval follows the fact's exact ACTIVE current-version pointer. Historical fact retrieval may return that current version plus genuine SUPERSEDED versions in bounded chronological order, but never MERGED, EXPIRED, forgotten, or unrelated versions. Exact, FTS, vector, and entity lanes contribute only ranks to versioned weighted reciprocal-rank fusion; raw scores from unlike lanes are never compared. Entity/currentness/temporal signals remain features for the strict reranker, not category gates or independent authority.

The administrator owns one installation-wide admission timeout for future Personal Memory attempts. It defaults to 30 seconds and is bounded to 1–120 seconds; expiry cancels the remaining optional Memory work and continues the ordinary answer without Memory rather than failing the chat run.

Outside the bounded broad current-fact inventory, the only query-independent context is a small set of explicit, current, user-global response preferences. Dynamic facts, preferences, and history are packed under their per-class budgets and a 1,800-token hard cap. Every selected item is authoritatively rejoined under owner, lifecycle/current pointer, expiration, exact evidence hash/offset, source dependency, entity-root, safety classification, compatible generation, source projection/revision, exclusion, suppression, and deletion fences before Phase B freezes the exact untrusted pack. Recovery reuses that frozen pack and never retrieves again.

Useful-memory prioritization is off by default and changes search-time ordering only. Its versioned multiplier stays within `[0.3, 1.5]`, applies only after mandatory relevance to candidates that already passed every hard fence, never changes a relevance threshold or removes an item, gives explicit or pinned current SLOT state a neutral floor, and dampens recency less for an explicit historical request. Turning it off immediately restores the pre-decay order while retaining only bounded use state. Only fact versions that enter the durable frozen pack receive one idempotent access touch for that binding; lane candidates, RRF/reranker-only rows, rejected rejoins, and past-chat chunks are never touched. Touch failure cannot fail the answer, change semantic lifecycle, or extend validity/expiration.

Only exact committed run items may produce browser Memory sources. The source contract receives friendly text and short-lived opaque owner/run/version/operation-bound references, never Memory repository IDs, hashes, scores, provider details, policy versions, revisions, or reasoning. Correct, Forget, Not relevant, and Open source revalidate the current authoritative item before acting; forgotten, excluded, deleted, stale, or non-current evidence cannot be replayed. Successful Open source may then redirect to the app's ordinary authenticated chat route. Public-share projection removes the entire private surface.

## History, Lifecycle, And Operations

Past-chat chunks preserve canonical `User:` and `Assistant:` labels, message boundaries, exact source maps, timestamps, and versioned chunk/source projections. Assistant text may support past-chat recall but never automatic fact evidence. History must pass the same format-aware secret defense and forced-strict semantic safety classification before reusable persistence. Source reads are personal-only and exclude Temporary, Project, deleted, excluded, pre-cutoff, stale-branch, stale-revision, and incompatible-generation data.

History indexing reuses a chunk only while its ordered message identities, projected safe content, edit snapshots, and projection versions remain exact. Append work rebuilds only the bounded overlap tail; branch divergence resumes after the longest common prefix, with a bounded full rebuild when incremental proof is unavailable. Each eligible retained chat may have one bounded current digest over exact safe chunks and messages. Targeted past-chat search admits attributable chunks, while an explicit broad history overview admits source-bound digests across chats. Neither chunks nor digests become automatic fact evidence, synthesized profile authority, or another source of hard facts.

Archive is organization only. Exclude immediately fences the retained chat from future recall and learning. Resume affects only messages created after its server-owned cutoff; it never schedules automatic historical backfill. Master/subordinate OFF periods and reset use durable generation, revision, cutoff, cancellation, and source barriers so delayed workers cannot commit old evidence.

One production Memory worker owns a complete declared job manifest, bounded leases, heartbeats, retry policy, and visible terminalization of unsupported legacy kinds. Startup verifies schema/write authority, registry completeness, key material, every actually admitted System/embedding credential envelope, and a rollback-only claim/heartbeat/commit transition without provider network I/O. Provider capability failures disable only the affected Memory stage; they do not prevent ordinary answers or unrelated deletion work.

Retrieval-version cutover inventories only owner-scoped content hashes and identity snapshots, admits an idempotent shadow rebuild, activates exactly one compatible generation after full-set and mandatory-vector proof, and retains superseded generation entries for an exact-set rollback. It never replays source content or dual-writes semantic observations. Current source settlement produces only the vNext extraction path; unfinished legacy candidate consolidation/verification work is terminalized and those kinds are absent from the active worker manifest.

Deletion duties are retryable and never terminally abandoned. Backup requires writer quiescence and every suppression key referenced by durable state; restore remains blocked until deletion, barrier, execution, and generation review is clean. [Persistence](PERSISTENCE.md) owns those mechanics, [Run contracts](RUN_CONTRACTS.md) owns answer admission, and [Security](SECURITY.md) owns secrets and egress trust.
