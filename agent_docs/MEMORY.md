# MEMORY

Owner: Native Memory maintainers
Scope: Personal Memory semantics, evidence, privacy, retrieval, learning, lifecycle, and recovery.

## Product Contract

Personal Memory is AIQSA-owned PostgreSQL state with five user controls: the master Memory switch, Search past chats, Learn automatically, opt-in pattern discovery, and opt-in useful-memory prioritization. Saved Memories remain directly manageable while Memory is paused; pausing a source stops new use and work without silently deleting retained data. Reset requires confirmation, fences future admission synchronously, and drains reusable Personal Memory through the durable deletion path.

Personal Memory has four reusable inputs: explicit Saved Memories, conservative direct-user learned facts, role-preserving personal past-chat chunks, and independently safety-admitted pattern propositions. Folder, Assistant, arbitrary user-facing scopes, generated profiles, user-facing conflict workflows, and Project Memory are outside this product. Existing Project Memory data may remain dormant, but Project runs create and receive no Personal or Project Memory bindings, context, sources, or jobs.

Temporary chats create no Personal Memory attempt, binding, item, source, receipt, counter change, or background work. Anonymous shares retain only their positive public snapshot and strip all Memory context, actions, references, sources, and lifecycle metadata.

## Actions, Evidence, And Safety

Natural-language Memory actions are decided by one bounded forced-strict System Model call over a locally secret-redacted projection of the current direct-user message. The exact current message remains server-side evidence and is never replaced by that projection. The answer model receives no Memory tools. Supported outcomes are `NONE`, `SAVE`, `UPDATE`, `FORGET`, `LIST`, `SEARCH`, and `RESET`; at most one further strict call may resolve an ambiguous owned target, and destructive reset still requires explicit confirmation. Mutation authority requires a byte-for-byte retained projection rederived from the authoritative current user turn plus an exact current owned target where applicable. Missing, invalid, or timed-out control yields `NONE` and cannot infer or replay a mutation. Assistant text, retrieved Memory, earlier turns, quotations, Search, Knowledge, MCP, tools, and attachments cannot authorize a mutation or become evidence for a user fact.

Durability, category, subject, correction, and target decisions may belong to forced-strict System Model contracts, but Memory safety does not. Local `Memory Safety Lite v1` returns typed UTF-16 spans and redacts PEM private keys, credential URLs, valid JWTs, known token formats, recovery codes, and Luhn-valid payment-card candidates longest-span-first; generic high entropy is count-only and never changes redaction or eligibility. A mixed message, query, digest, or explicit mutation retains every meaningful safe source span, while a secret-only, empty, oversize, control-unsafe, or independently ineligible projection is fenced. The same last-line projection runs before Memory control, extraction, digest generation, embeddings, query embeddings, reranking, aggregation, answer context, indexing, and debug serialization. New fact versions store synchronous local policy outcomes with null semantic-classifier execution/provider/model fields; chunks apply the same policy synchronously without a classifier. Ordinary personal, medical, financial, preference, and relationship text is not a secret class. Raw recognized secrets may remain only in the authoritative Chat message under the Chat contract and never in a Memory derivative.

Automatic learning gives each eligible direct-user message one destructive-generation-bound deterministic extraction job after its committed Normal turn. Preparation reloads that immutable target plus a contiguous suffix of at most two immediately preceding safe user/assistant turn groups and current facts as opaque context refs; the complete message projection, including the target, is capped at six messages and 8,000 redacted characters. Only the exact current direct-user target can supply testimony or evidence. Prior user text and visible completed assistant text may resolve a reference, relation, correction, or temporal expression, but are retained only as revalidated dependencies; assistant text never attests a user fact. Later turns and branch changes that retain the target and every required dependency on the active message-DAG path do not invalidate it; a path that excludes one, source deletion or edit, exclusion, pause intervals, suppression, Project boundaries, and destructive generation changes still fail closed. One strict extraction may return zero to four independently validated observations with a language-neutral semantic frame and explicit zero-based exact-occurrence references; offsets use UTF-16 wire units and preserve source Unicode exactly. Every high-risk candidate class is resolved together by zero or one further forced-strict semantic adjudication call for that source. There is no later entity, ownership, temporal, or relation provider call. Durable, future-useful, allowlisted, storable `HIGH` observations may participate in authoritative current state. A narrowly admitted direct-user `MEDIUM` assertion is stored only as a lower-authority proposition: it remains retrievable as supporting context but cannot become core, supersede or override authoritative state, or feed pattern synthesis. `LOW` and authority-critical uncertainty are rejected.

The automatic write path is append-only: a new proposition commits its fact, immutable version, exact evidence, and event atomically. New automatic evidence records the direct-user quote, UTF-16 offsets, source-content hash, projection version, and separately domain-versioned observation/evidence fingerprints. An exact normalized duplicate from another direct source attaches fresh evidence and reinforcement without creating a competing version; replay of the same evidence fingerprint has no semantic side effect. Stored branch generation is observation-time audit, while current reuse re-proves message membership in the active DAG path. Explicit Saved Memory retains higher authority. Semantic persistence does not wait for embeddings: compatible indexing is queued independently and remains retryable after the fact commit.

Automatic identity is server-owned and versioned. An allowlisted dimension-bearing `SLOT` represents one mutable subject/predicate/dimension truth; weak or unsupported identity falls back to a normalized `PROPOSITION`. A direct relationship observation about a named third party is a proposition whose exact mention may bind an owner-scoped `PERSON` entity as provenance, never the user's self subject. Category never participates in identity, required dimensions are never guessed, and the single product-status vocabulary keeps considering, ordered, owned, borrowed, shared, and work-device states distinct.

Entities are owner-scoped identity and retrieval aids, not provider semantic authority. Product-status SLOT identity is `slot:v3` anchored to the canonical `subjectEntityId` root; `PRODUCT` and `DEVICE` are one compatible family, while provider label, brand, and model never enter the durable fact key. Resolution is conservative: an exact supplied context root precedes a server key or exact supported alias, creation requires an exact named/nominal source span, broad/specific lexical similarity never merges entities, and only a bounded `ENTAILED`/`HIGH` exact-alias collision may invoke the idempotent merge path. One source-valid alias-support authority governs context, resolution, relations, synthesis, rebuild, and retrieval; pronouns are never aliases, final support loss fences reuse synchronously, and an automatic-only zero-support root may become terminally `RETRACTED`. Historical merge links remain immutable, merged children never promote themselves, and a fresh exact observation creates a new root rather than resolving a retracted one.

Semantic lifecycle and Safety Lite admission are independent. A new automatic version receives its synchronous local classification in the semantic commit and does not wait for a safety provider; legacy `PENDING`, `UNCERTAIN`, or surviving content-bearing `SECRET_FENCED` rows are handled only by bounded owner/source/lifecycle-authorized reprojection. Purged or retracted legacy rows are never revived. Same identity/value evidence reinforces the immutable canonical version; a different value for the same slot is a non-current relation-pending version. Candidate rejection terminalizes only that candidate and cannot remove an older safe current.

Relation resolution consumes only the stored semantic frame, the source-batched adjudication, code-owned values, opaque refs, and a fresh locked snapshot. A compatible representation merges into one canonical truth without inventing history; a genuine allowed state change or explicit correction supersedes and preserves the prior state. Pointer changes, cross-fact moves, and entity/representation merges require a fresh valid target plus `ENTAILED` and `HIGH` adjudication authority. Explicit current Memory outranks conflicting automatic evidence, retrospective states do not silently replace the present, and missing, stale, or ambiguous authority becomes a durable conflict without another provider call.

Reuse expiration is set only from an exact referenced expression plus a validated language-independent calendar operation and remains independent from domain validity. Invalid optional temporal metadata degrades to null; an explicit TTL that cannot resolve safely rejects that candidate rather than storing it indefinitely. Ordinary reads, action/source projections, rebuilds, and embedding rejoins synchronously require an absent or future `expiresAt`; background cleanup is not an admission boundary. A write under the same identity first materializes any due current version as expired, clears its reusable pointer/index, and never resurrects an older superseded version.

Pattern discovery is off by default, forward-only from its first-enable boundary, and independent of ordinary chat and direct Memory. A bounded scheduled strict call may derive only lower-authority depth-one proposition patterns from at least three distinct currently eligible direct versions inside one conservative entity/semantic/time cluster. Ordinary scheduling requires a changed eligible source set, thirty minutes without new evidence, and either eight new evidence-bearing chats, twelve changed direct facts, or a twenty-four-hour low-activity fallback; a twelve-hour hard cooldown limits ordinary provider frequency but never acts as a timer by itself. Provider inputs use only call-local opaque entity handles resolved against frozen server-side bindings, never repository entity IDs. Every PATTERN retains its per-pattern ingestion identity, exact source-set identity, succeeded execution receipt, immutable `SYNTHESIZED_FROM` relations, and synchronous Safety Lite admission. It never owns hard SLOT state and is demoted below direct Memory. Disable stops new synthesis without moving the boundary or deleting valid patterns. One reusable-fact authority contract governs direct and evidence-less PATTERN admission through incremental and full indexing, embeddings, retrieval, selected-item rejoin, and frozen packing; PATTERN admission is explicitly closed unless a targeted-current plan opts in. Source, dependency, lifecycle, expiration, or destructive content-generation loss fails authoritative rejoin immediately. Search-index cutover advances the retrieval revision and active-index pointer but not that destructive content generation, so reindexing cannot orphan an otherwise valid PATTERN. Bounded reconciliation retracts invalid patterns immediately and may schedule one cooldown-bypassing targeted replacement only when at least three exact direct sources remain, preserving direct memories and audit lineage.

Facts and versions remain immutable evidence records. Active v1 Personal facts are user-global; legacy non-global and Project records are not broadened or destructively migrated. Forget/edit/reset synchronously advances the applicable fences before deferred derivative cleanup, so queued jobs, rebuilds, stale vectors, or unchanged evidence cannot resurrect content.

## Retrieval And Run Admission

Each eligible Normal send/regeneration uses the run's two-phase boundary. Phase A accepts a private non-dispatchable run and one content-bounded retrieval attempt before optional Memory utility calls. Every non-empty ordinary answer begins with a deterministic local plan over the bounded `originalSanitizedQuery`; enabled facts and past chats remain eligible even when control is missing or says Memory is not useful. A valid strict System Model decision may narrow a deliberate profile, historical, past-chat, aggregation, or response-preference route and may add a semantic rewrite, but that rewrite supplements rather than replaces the original. For a genuinely multi-part request it may additionally supply at most two standalone facet or boundary subqueries; these supplement both the original and rewrite, never encode the final comparison or calculation, and remain absent for a single-facet lookup. The query bundle is deterministically deduplicated and bounded to four semantic and two temporal variants. Control failure or an invalid enriched plan preserves mutation `NONE`, records a content-free fallback reason, and runs the base plan as `DEGRADED` when it yields evidence. A valid pure explicit action remains the only route that skips ordinary read retrieval. Entity hints are limited to eight exact query occurrences with owner-validated opaque refs and grant no fact, source, lifecycle, safety, or mutation authority; patterns default off and are available only to targeted-current retrieval. Exact fact text, supported entity aliases, PostgreSQL FTS, vectors, recent/temporal signals, and targeted digest navigation are independent candidate signals: an unavailable signal is recorded and the remaining signals continue. Weighted rank-only RRF groups duplicate projections by their source-bound evidence root, and source diversity changes bounded ordering without imposing a per-source quota. Query embedding, semantic sorting, and aggregation planning are independent optional utilities: missing, partial, invalid, timed-out, or unavailable embedding preserves local lexical/entity/temporal/recent lanes; the independently selected score-only reranker receives dated, speaker/source-attributed, current-or-historical safe candidates after authoritative filtering and cannot make authority decisions; partial scores preserve RRF ordering for unscored candidates; unavailable sorting preserves the full fused RRF order, including episodic history; unavailable aggregation preserves the underlying pack. With no usable candidate signal, dynamic Memory is empty and the ordinary answer remains available.

A bounded local EN/RU temporal parser anchors relative expressions to the accepted run timestamp in the accepted request zone, or the recorded UTC fallback when no request zone exists. A high-confidence interval may hard-filter only its dedicated temporal lane; a lower-confidence match changes ordering only, and every matched temporal query also executes a time-unrestricted fallback lane. Ambiguous, invalid, or absent interpretation cannot suppress ordinary retrieval, and temporal diagnostics expose only parser state/type/confidence and candidate counts. Reliable relative dates in fact extraction and chat digests retain their original wording/source time while adding the grounded absolute date; no stage invents an unsupported event time.

The plan names one closed mode: current profile, targeted current facts, historical fact memory, past-chat search, or history overview, together with a compatible current, historical, as-of, between, or any-time intent. Current fact retrieval follows the fact's exact ACTIVE current-version pointer. Historical retrieval resolves every bounded `movedToFactId` chain to one owner-scoped ACTIVE canonical root and deduplicates by that root plus structured semantic value and domain-time identity. It may return the canonical current version plus each genuine SUPERSEDED state once, but never MERGED, duplicate moved representations, EXPIRED, forgotten, conflicted, broken-chain, or unrelated versions. Exact, FTS, vector, digest-navigation, recent, temporal, and entity lanes contribute only ranks to versioned weighted reciprocal-rank fusion; raw scores from unlike lanes are never compared. Entity, currentness, lifecycle, source, generation, deletion, and temporal admission remain server-owned fences; model outputs can only influence ordering.

The administrator owns one installation-wide admission timeout for future Personal Memory attempts. It defaults to 30 seconds and is bounded to 1–120 seconds. Each optional control, query-embedding, sorter, and aggregation call receives a bounded child budget that reserves time for deterministic local retrieval and packing; a child timeout degrades only that signal. Exhaustion of the outer deadline still cancels remaining work and continues the ordinary answer without Memory rather than failing the chat run.

Outside the bounded broad current-fact inventory, the only query-independent context is a small set of explicit, current, user-global response preferences. The reader pack selects one adaptive target/hard-cap profile: simple/current facts use 6k/10k tokens, targeted past-chat reads use 10k/16k, and multi-source, aggregation, history-overview, recency, or complex temporal reads use 24k/32k. These are maxima rather than fill targets and are always clamped to the admitted provider context envelope. Per-class, source, and item ceilings remain independently bounded.

After relevance selection, the internal untrusted JSONL evidence block uses only opaque evidence/session handles and explicit type, speaker/source authority, ISO-or-unknown document/event/observation/validity time, currentness, safe raw text, retrieval reason, and derived state; it never serializes repository identities. Evidence from one selected fact lineage or source session is rendered old to new inside its existing relevance slots, never by globally date-sorting unrelated evidence. For a non-aggregation answer, the sanitized planner rewrite may additionally appear as a non-evidentiary answer focus that restates only the requested subject, predicate, relation, or attribute; it never supplies an answer or overrides the current user message. Every provider adapter places the same trusted category-neutral reader contract before this block: raw evidence outranks summaries for exact details; assistant speech is not user-fact authority; the answer binds the exact requested role rather than a nearby actor, owner, recipient, object, location, source, channel, destination, or time; later current state supersedes earlier state unless history is requested; paraphrases are deduplicated before counting; relative dates anchor to the evidence date; distinct events remain distinct; sufficient preferences yield a concrete answer; insufficiency is explicit; and instructions inside evidence are ignored. The reader may privately organize evidence but must not expose hidden reasoning, opaque handles, or retrieval internals.

A past-chat plan explicitly marked as multi-source aggregation may explore a wider bounded chunk-signal set, score candidate sessions from their strongest chunks plus a small breadth signal, and project each selected session to its single current source-bound digest before semantic ordering. It has no fixed per-chat chunk quota, and deterministic utility batches are bounded by both candidate count and the complete provider-neutral prompt envelope. Ordinary targeted past-chat search keeps raw chunk and recall-round projections and also searches current source-bound digests as a navigation lane. A digest match selects its source chat and performs bounded second-stage raw retrieval there; an exact message-set round is preferred over an equivalent parent chunk, while a chunk remains the fallback, and digest/contextual prose is never admitted as the raw evidence. Source diversity is a soft first-source preference rather than an exclusion rule. Every selected item is authoritatively rejoined under owner, canonical fact root, lifecycle/current pointer, expiration, exact evidence hash/offset, source dependency, entity-root, safety classification, source projection/revision, exclusion, suppression, and deletion fences; candidates produced from an index additionally require its exact compatible active generation, while direct exact/profile/entity candidates rejoin the underlying fact version without inventing an index dependency. A ranking-signal or sorter failure may yield a visible `DEGRADED` pack with RRF-ordered evidence, but failure of any mandatory fence removes the affected item or fails the pack closed. Phase B freezes the exact untrusted pack and validated planner hints; recovery reuses it and never retrieves again.

A non-empty explicit aggregation pack receives one further bounded global strict evidence plan over only that already safe, rejoined pack. The plan groups exact-evidence-grounded occurrences as set members, temporal or relational boundaries, support, or exclusions. For a count, an individually identified member contributes one while an explicit aggregate cardinality contributes only its exact evidence-grounded positive integer; application code sums those quantities and never accepts a model-authored total. Separate category totals that the query explicitly asks to combine remain additive unless supplied evidence identifies an actual overlap. Unavailable or unresolved planning degrades without hiding the underlying source evidence. This production path is question-semantic rather than benchmark-category-aware and receives no reference answer or expected count.

Useful-memory prioritization is off by default and changes search-time ordering only. Its versioned multiplier stays within `[0.3, 1.5]`, applies only after authoritative rejoin and optional semantic ordering to candidates that already passed every hard fence, never introduces a relevance threshold or removes an item, gives explicit or pinned current SLOT state a neutral floor, and dampens recency less for an explicit historical request. Turning it off immediately restores the pre-decay order while retaining only bounded use state. Only fact versions that enter the durable frozen pack receive one idempotent access touch for that binding; lane candidates, RRF/reranker-only rows, rejected rejoins, and past-chat chunks are never touched. Touch failure cannot fail the answer, change semantic lifecycle, or extend validity/expiration.

Only exact committed run items may produce browser Memory sources. The source contract receives friendly text and short-lived opaque owner/run/version/operation-bound references, never Memory repository IDs, hashes, scores, provider details, policy versions, revisions, or reasoning. Correct, Forget, Not relevant, and Open source revalidate the current authoritative item before acting; forgotten, excluded, deleted, stale, or non-current evidence cannot be replayed. Successful Open source may then redirect to the app's ordinary authenticated chat route. Public-share projection removes the entire private surface.

## History, Lifecycle, And Operations

Past-chat history preserves canonical `User:` and `Assistant:` labels, message boundaries, exact source maps, timestamps, and versioned source projections. Parent chunks remain a fallback search unit; a recall round is one paired turn or standalone visible message with an exact message-set evidence root and parent link. Its one contextual narrative key may use at most two prior groups, is generated in bounded chat batches, and always retains the raw round for exact terms; unsupported, invalid, or unavailable output falls back to that raw key without blocking indexing. Contextual keys are search projections, never evidence: a hit must authoritatively rejoin the bounded raw round. Private tool calls/results do not currently participate in the visible Chat message DAG and remain excluded rather than copying tool payloads into Personal Memory; the reserved tool-event round kind applies only if a future client-safe conversational source contract admits such an event. Assistant text may support past-chat recall but never automatic fact evidence. History applies Safety Lite locally before reusable persistence; System Model availability is relevant only to optional contextual keys and digests, never to raw lexical admission. Source reads are personal-only and exclude Temporary, Project, deleted, excluded, pre-cutoff, stale-branch, stale-revision, and incompatible-generation data.

History indexing reads the checkpoint and active-path metadata before message content. It reuses a chunk or round only while its ordered message identities, projected safe content, edit snapshots, admission, parent/source proof, and projection versions remain exact. A normal append loads and projects only a bounded contextual overlap plus the changed tail; branch or edit divergence rewinds to a bounded affected suffix, while invalid checkpoint proof, a pipeline change, or a source-context transition that invalidated reusable projections requires a bounded full rebuild. Such a transition records an explicit rebuild-required checkpoint marker instead of relabeling old proof as the current pipeline. Round configuration is generation-bound: a complete compatible shadow generation activates through one pointer only after every eligible retained chat has a current-pipeline checkpoint, retains the exact prior generation for rollback, and keeps chunks alongside rounds during the compatibility generation. Content-free work counters make those bounds verifiable without wall-clock claims. Each eligible retained chat may have one current digest whose exact source maps cover the complete bounded eligible chunk/message sequence. Within its bound, the digest preserves distinct concrete user-authored episodes and autobiographical details even when they are incidental to the chat's main request, prioritizing those attributable details over generic assistant exposition. The digest advances from its previously Safety-Lite-projected derived text plus a bounded exact delta, skips generation when the coverage fingerprint is unchanged, and periodically or after divergence performs a policy-versioned bounded hierarchical rebuild over early and late history. Digest unavailability or invalid output commits the safe raw projections with a content-free degraded reason instead of failing their indexing. Ordinary targeted past-chat search admits attributable chunks and rounds through exact, lexical, compatible vector, and digest-navigation signals; a digest-only match must expand inside its current source chat and rejoin authoritative raw evidence before packing. Explicit multi-source aggregation uses bounded raw signals only to select sessions, then admits each session's current attributable digest; an explicit broad history overview also admits source-bound digests across chats. Neither chunks, rounds, contextual keys, prior digests, nor current digests become automatic fact evidence, synthesized profile authority, or another source of hard facts.

Archive is organization only. Exclude immediately fences the retained chat as a future recall and learning source, but does not disable Personal Memory retrieval into that chat; Temporary and Project chats remain fully outside Personal Memory. Resume affects only messages created after its server-owned cutoff; it never schedules automatic historical backfill. Master/subordinate OFF periods and reset use durable generation, revision, cutoff, cancellation, and source barriers so delayed workers cannot commit old evidence.

One production Memory worker owns a complete declared job manifest, bounded leases, heartbeats, retry policy, and visible terminalization of unsupported legacy kinds. Startup verifies schema/write authority, registry completeness, key material, every actually admitted System/embedding credential envelope, and a rollback-only claim/heartbeat/commit transition without provider network I/O. Provider capability failures disable only the affected Memory stage; they do not prevent ordinary answers or unrelated deletion work.

Semantic deployment cutover is an explicit operator gate. Its inventory reads aggregate counts only and never projects Memory content, aliases, entity labels, provider bodies, prompts, emails, or raw owner identifiers. A zero inventory requires an explicit no-op disposition; retained nonzero rows require an explicit safe disposition and remain excluded from exact-vNext context, indexing, embedding, retrieval, rejoin, and frozen packs. Cutover never upgrades legacy rows to direct authority.

Retrieval-version cutover inventories only owner-scoped content hashes and identity snapshots, admits an idempotent shadow rebuild, activates exactly one compatible generation after full-set and mandatory-vector proof, and retains superseded generation entries for an exact-set rollback. It never replays source content or dual-writes semantic observations. Current source settlement produces only the vNext extraction path; unfinished legacy candidate consolidation/verification work is terminalized and those kinds are absent from the active worker manifest.

Deletion duties are retryable and never terminally abandoned. Backup requires writer quiescence and every suppression key referenced by durable state; restore remains blocked until deletion, barrier, execution, and generation review is clean. [Persistence](PERSISTENCE.md) owns those mechanics, [Run contracts](RUN_CONTRACTS.md) owns answer admission, and [Security](SECURITY.md) owns secrets and egress trust.
