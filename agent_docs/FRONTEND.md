# FRONTEND

Owner: Frontend maintainers
Scope: Product composition, client/server state, responsive interaction, visual system, and UI trust.

## Product And Ownership

AIQSA ships one conversation-first presentation: Chat is primary, workspace navigation secondary, and Control Center manages installation resources. There is no parallel classic/new renderer, `/v2` product, duplicate API client, or hidden fallback UI. New composition must preserve applicable Chat, files, Search, Knowledge, Memory, Assistant, MCP, account/share, and administration capabilities through one discoverable path.

Server pages authenticate/authorize and pass least-data initial props. `lib/contracts/` owns decoded client-safe wire shapes. Focused workspace, thread, composer, run, Memory, Assistant, Knowledge, and admin stores/controllers own browser state and mutations; view components consume their contracts and callbacks. Do not mirror server authority, repository rows, or the same async resource in component-local state.

Async state is source-keyed. Capture the resource/chat/session key when work starts; settle only that key; abort or ignore stale results on navigation. Preserve independent chat drafts/uploads/runs, and do not let a late response overwrite a newly selected resource. Server responses remain authoritative after optimistic mutations; malformed payloads fail visibly rather than becoming guessed state.

Server data includes identity, entitlements, catalogs, chats/message branches, lifecycle/outcomes, resources, and persisted preferences. Browser-only state includes open overlays, focus return, hover/selection presentation, keyed unsent drafts, and in-flight handles. Theme is a browser presentation preference, never account/chat content.

## Chat Composition

The shell is an icon rail, a second column, and one reading column with thread over composer. The rail carries the permanent destinations (Chats, Projects, Library; Settings, Control Center, account) and the second column's content follows the selected section: the personal chat list, the active Projects list or one selected Project's own chats and folders under its name, or the Library's section list. Desktop begins at 1024 CSS pixels; compact uses 768–1023px, and mobile uses 767px and below. On desktop, collapse hides only the second column while the rail stays and the header gains the reopen and New Chat controls; on compact widths the second column is a scrim-backed drawer beside the persistent rail; on mobile widths there is no rail and no header bar — the rail destinations live in the drawer's footer and floating islands (menu; the model selector; New Chat and actions) sit over a faded band of the thread, without a title. New Chat remains reachable in every state. The concrete model is chosen from the chat header on every width, blank chat included; the header selector only anchors the composer-owned picker, and the composer row carries this message's tools (Add, Search, Knowledge, MCP, Send). Settings is one modal with vertical tabs that gathers appearance, chat defaults, Memory, Connected apps, MCP, data, and account; a Data row may open a focus-safe sub-view under that section's own Back control inside the same modal. MCP servers are ordinary Settings rows with a switch, and a server that still needs personal values or an external-account connection shows that step in place of the switch. The Library is a second column of sections beside one reading column; a resource opened from a section (a Knowledge base, the documents catalog, a document) is a sub-view of that column under the Library crumb with the Library's own Back control, never a second full-screen surface. Composer menus are anchored popovers without a scrim. Branches and generated-output preview are temporary overlays/sheets, never pinned diagnostic columns.

Shared Projects are first-class workspace contexts in that same shell. Their folders and all chats are visible to every current Project member, user turns show durable author attribution, and role-gated management stays in Project surfaces. Creation asks only for a name and optional description, uses a safe eligible default model when one exists, and otherwise creates an explicit setup-required workspace whose first answer remains blocked until an eligible shared model is configured. The Projects reading surface has no second project search or duplicate creation control, apart from the actionable CTA in a genuinely empty landing state; its overview may retain the direct blank-project composer so starting a shared conversation does not require an extra navigation step. On mobile, the same overview puts its local folders and chats ahead of that in-flow composer instead of shrinking the desktop setup dashboard. Member/resource management uses searchable, paginated, server-filtered pickers and consequence previews rather than internal IDs. Project composer controls come only from the active Project resource set and never mix personal catalog entries; a blank shared-chat draft stays local until its first successful send. A narrow desktop Project-context rail may show scope, members, resources, Memory, activity, and the explicit `Personal Memory is off` boundary; it is shared-workspace context, not a run inspector, and remains reachable in compact composition. Leaving or losing access closes Project synchronization and clears stale selection rather than presenting personal fallback data as Project state.

The composer owns one keyed draft, attachment queue, selected concrete model, optional Assistant, Search/Knowledge plans, manually selected Skills, supported next-run controls, Send, and Stop. Editing an existing user message is turn-scoped: its auto-growing inline editor owns a separate draft and error, keeps sent attachments read-only, states that Send creates a branch, and never replaces or clears the composer draft. Ordinary MCP choice is always visible as Auto, Load all, or Off; only an explicit user action changes that choice, while enabling/configuring servers remains a separate Settings action. An unavailable Auto discovery offers Retry in Auto and a distinct `Use Load all` action; mode changes only when the latter is clicked, and both actions start a new regeneration. Revisions, runtime generations, discovery epochs, and raw tool inventories are not ordinary composer concepts. Enter submits only under the current keyboard/IME contract; multiline editing and attachment progress/errors remain usable. Provider/model/control availability is server truth and no UI fallback silently changes the selected target.

Workspace is a chat-level composer toggle, not a model/runtime picker. It remains visibly on or off across reload, shows the server-projected environment and internet state, and is disabled with an accessible reason when installation policy, runtime health, or model tool capability is absent. Only an enabled Workspace broadens that chat's upload picker to opaque formats; turning it off restores the ordinary strict upload contract. Branch changes and regeneration never claim filesystem rollback.

Conversation content is a readable document, not a grid of cards or run receipts. User messages retain ordinary edit/branch/delete actions. Assistant messages expose normalized live state, answer text, safe Markdown/code/math, inline citations, Sources only when present, generated outputs, explicit mutation feedback, copy/regenerate/delete, and Branch navigation. Knowledge citations use the same responsive Source rail for prose, table, form, OCR, image-caption, page, and heading evidence; opening one shows the exact authenticated Source Version, locator, and excerpt without exposing scores, focused requests, manifests, raw identifiers, or a second document editor. An answer has one anatomy: a single process disclosure above the text, a clean body, and one actions row below. While the run works, the disclosure's slot holds the live status; once the answer starts it becomes a fold whose label reads the way a person says it ("Thought for 12s", "Worked for 1m 4s", "Used 2 memories"), never a count of tool calls or sources, and it is absent when nothing happened. Inside, in order: Thinking, Steps (only user-legible server/tool names, round, state, and duration), and Memory recall as one row per fact whose Correct / Not relevant / Forget verbs wait behind a row menu; a reached-limit warning stays visible outside the fold, and a committed memory save is a one-line notice under the line with its Edit / Forget / Manage verbs behind the same kind of menu. The actions row keeps the branch pager and a `Sources · N` chip always visible and hover-reveals only the verbs; the chip expands the source list in place under the row, where inline citation marks point. The work time is the run's admission-to-first-token fact, measured on the client only for the answer in flight; elapsed time never invents it. Search traces, request previews, tool arguments/results, retrieval scores, raw event timelines, and per-answer usage are not hidden inspector surfaces or a separate right-hand panel.

Workspace activity reuses the answer process disclosure as a chronological timeline built from the server's structured entries (kind and phase) with client-owned copy: lifecycle rows (starting, attachments prepared, ready, exporting, recreated with its runtime-loss warning, stopped), file operations with `/workspace`-relative paths and original inbox names, and command cards that open into command, working directory, bounded stdout/stderr, exit code, duration, and a copy control. Failed cards open on their own, successful ones stay compact, an async execution is one card, and raw tool identifiers, runtime ids, or unbounded output never reach the thread; the fold reads `Working in Workspace…` while live and `Worked in Workspace for …` once settled. Generated files remain the canonical download block with name, type, size, and an authenticated Download action after settlement and remain after reload or sandbox loss; an owed or failed export is stated above them without hiding files already settled. A model-written `sandbox:` link resolves to a real download only for an exact generated file of the message's own run and otherwise renders as inert text. Stop is explicitly non-destructive and the composer's running-command state follows the live stream, never a stale event. Reset and Download workspace are chat actions: Reset names the filesystem consequence, requires confirmation, prevents duplicate submission, and preserves messages/attachments/generated files; Download workspace reports its own loading/error result and never creates an LLM run. All controls remain keyboard-labelled, focus-safe, and reachable without hover across the existing responsive layouts.

Loading failure is not empty state. Pending, unavailable, disabled, revoked, degraded, cancelled, partial, and complete remain visually and semantically distinct. Live labels come only from normalized lifecycle state; an active lifecycle status may use a restrained text shimmer, while elapsed time or animation never invents progress, confidence, sources, cost, or completion. Reduced-motion mode renders the same status without animation.

While a Project is selected, one authenticated SSE stream drives ordered refresh from client-safe persisted projections. Retained cursor replay covers reconnect, an expired cursor triggers explicit canonical resync, and bounded fallback refresh preserves usability during transport failure. Another member's committed chat, question, durable partial answer, tool/Search activity, safe sources, and terminal state appear without reload; local drafts and scroll ownership survive background refresh. This is near-live shared work, not presence or ephemeral-event synchronization: the UI does not claim who is online or recreate provider-only events that were never durably projected. An internal Copy link selects and authorizes the stable Project/chat destination without creating a public share or widening access.

Auth, public share, Settings/Library, Memory, Assistants, Skills, Knowledge, and Control Center use the same ownership rules. Background Project refresh does not reset the active Settings tab or dirty drafts. Project chats never appear in Personal Memory/history surfaces. The global command palette is absent; personal chat lookup is the sidebar's scoped `Filter chats…` field over the current user's personal chats (server-side, paginated), never a global command or cross-Project search. A selected Project's own column may locally filter only its already-loaded shared chats. Skills are a first-class Library section rather than an overlay; the composer's responsive picker reuses the same list while keeping its selection task local. Both entry points are lazy: shell mount issues no list request, entering either surface loads metadata pages, search stays server-side, and full instructions load only for a chosen detail. Every owned or shared row opens that detail; selection uses a separate ordered Use/Remove action. Owners manage current audiences, blocked Unshare dependencies, and Delete impact from the detail without exposing revision/runtime terminology. The composer presents Assistant-included Skills as read-only and manual Skills as a distinct editable ordered set. Skills remain text-only with no code, tool, MCP-dependency, or auto-activation affordance. Installation policy owns positive-integer tool-call, tool-round, MCP Auto per-discovery result, and MCP Auto discovery-timeout defaults. Calls and rounds have no arbitrary UI maximum; Auto discovery remains bounded by the general MCP run-plan tool limit and its interactive timeout boundary. The System Model surface distinguishes MCP Auto Ready, Verification required, and Not supported states; only the saved supported deployment that needs evidence offers the explicit charge-bearing verification action. The Admin Knowledge surface keeps embedding and PDF processing in one route editor: Local, System Model Direct PDF, and System Model Vision are mutually exclusive future-only profile choices, unavailable capabilities stay disabled, and model routes disclose the exact pinned System Model destination and external page representation before activation. Activation/rollback rebuilds future artifacts without exposing private corpus data, raw revisions, or a separate diagnostics tab. The same section exposes one future-only `Maximum Knowledge searches per answer` value (1–32), explains that small corpora fitting 70% of model context are supplied whole with zero searches, and does not expose route, ranking, or token-budget knobs. It also exposes future-only parallel document processing (1–64, default 8); saving changes only subsequent background work and never widens documents already processing. Secret fields state preserve/replace behavior and never echo values. Resource rows open their primary detail directly; destructive actions name the target/consequence and confirmations are proportional. Public share renders only its sanitized read-only snapshot.

Inbound Personal Memory clients have a distinct user-owned **Connected apps** Settings section; never mix them with outbound MCP servers available inside AIQSA chats. Consent and revoke surfaces name full fact read/add/change/delete authority and the chat-history exclusion. Revocation is presented as terminal access loss while explicitly confirming that stored Memory facts remain.

Administrator Knowledge health exposes only bounded aggregate search-backend availability, projection ready/pending/failed counts, and worker freshness with actionable human copy. It never exposes endpoints, physical index names, worker identities, queries, document identities, raw failure messages, or provider details.

Ordinary Knowledge creation asks for a name, optional description, and optional files. The same Knowledge surface exposes bases and reusable documents; `Source` remains an internal data/wire term. Document detail keeps version history behind progressive disclosure, shared documents are read-only, and Add to base, Remove from base, and Move document remain distinct consequence-bearing actions. Chat, Project, and Assistant configuration may select an authorized base, individual document, or `All my knowledge`; the server remains the scope authority. List and detail surfaces show current document count, readiness, updated time, access, safe support references, and product actions. A usable artifact always presents as `Ready`; processing caveats may add at most one bounded plain-language note and never imply recovery. `Needs attention` is reserved for an unusable target when the server projects an executable Reprocess action; otherwise an unusable document is `Unavailable`. Processing profiles, revisions/generations, dimensions, fingerprints, chunk counters, raw warning codes, quality scores, and raw failure codes are not ordinary UI concepts. Reprocess never asks the user to choose processing infrastructure. Owner catalogs provide a distinct Trash filter for recoverable bases and documents with deletion and scheduled-purge times. Restoring a document into multiple still-valid base memberships requires an explicit consequence confirmation. Permanent deletion requires its own confirmation, returns a durable pending state, disables Restore after admission, and explains whether canonical documents survive.

Knowledge answer state is explicit and concise. Zero ready selected Sources show processing without implying that retrieval ran; a ready subset shows a short limitation alongside the answer. Exactly zero candidates, model-declared insufficient evidence, retrieval failure, answer-provider failure, and status/citation-contract failure remain distinct. Technical failure is never phrased as “the documents contain no answer,” and client projections contain no raw query, Source text, internal identifiers, scores, or provider details.

## Responsive And Interaction Contract

Composition follows available space and input capability, not device names. The current shell changes from normal-flow sidebar to collapsed layout and then a scrim-backed drawer at its owned breakpoints; source CSS/tests own exact values. Width never creates a second store, draft, selection, or navigation tree. Composer and overlays respect dynamic viewport, safe areas, software keyboards, and one deliberate local scroll owner.

The page has no horizontal overflow. Code, tables, formulae, long URLs, and exceptional data grids wrap truthfully or own named local scrollers. Composer stays in layout rather than covering the last answer. Coarse-pointer primary actions have comfortable touch targets, and no phone/tablet workflow depends on hover or drag precision.

Dialogs/drawers/sheets isolate the background, contain Tab where modal, own Escape/nested-confirmation priority, focus a deliberate entry control, and restore the opener when still valid. When a responsive transition hides focused navigation, focus moves to the reachable reopen control. Text, draft, run, and selection state survive geometry changes.

Dedicated WCAG certification is deferred, but semantic labels, keyboard-safe entry, focus ownership, readable overflow, responsive access, touch operation, and existing reduced-motion behavior are current contracts.

## Visual System

The character is a quiet, precise reading workspace on a cool dark-navy canvas—not a generic dashboard, decorative AI demo, or research debugger. Cyan is the only control accent (actions, selection, focus, live state); violet marks only the answer phase (streaming cursor, live status, tool spinner, Knowledge citations) and never appears in controls, chips, navigation, or Settings. Establish hierarchy with placement, measure, type, and whitespace; add a surface, separator, shadow, accent, or status color only when it communicates a distinct job or observed state. Glow belongs only to live state and the sign-in mark, gradients only to that mark. Avoid card grids around prose, badge carpets, ornamental gradients/glass, oversized hero copy, and permanent toolbars of every run control.

`styles/tokens-v2.css` is the sole palette-value boundary. Components consume semantic canvas/sidebar/surface/text/border/accent/status/radius/shadow/motion roles, not raw palette colors or local light/dark recipes. The product exposes exactly `system`, `light`, and `dark`; normalized cookie state owns first paint, recognized LocalStorage may repair it after hydration, and System follows the OS without becoming a third palette.

Use bundled Golos Text for UI/document prose and JetBrains Mono for code/identifiers/config. Answers keep a readable measure and generous line height; metadata remains legible rather than miniaturized. Use the established spacing/radius/depth tokens; reserve shadow for composer/floating overlays and pills for true compact status/filter/tag shapes.

Controls define applicable rest, hover, active, selected, disabled, busy, invalid, success, and destructive states. Busy actions keep their label and reject duplicate submission. Fields retain labels and associated errors. Empty/error states explain the next valid action. Motion communicates state/spatial origin, never decorates idle surfaces or animates layout during token streaming; reduced motion remains deterministic.

For material UI changes, inspect representative Chat and Control Center states in light/dark, long content, the smallest supported viewport, short landscape, and relevant breakpoint/focus transitions. Tests assert behavior, roles, state, containment, geometry, overflow, and theme—not screenshots or implementation shape. Select the lane in [Testing](TESTING.md).
