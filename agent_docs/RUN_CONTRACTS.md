# RUN CONTRACTS

Owner: Run pipeline maintainers
Scope: Accepted execution, context, tools, evidence, recovery and outputs.

[Critical invariants](CRITICAL_INVARIANTS.md) owns historical immutability, tenancy and privacy. Executable contracts live in [runs](../lib/server/runs/) and their domain owners.

## Admission And Context

Admission freezes exact non-secret execution, dependency, credential and budget bindings from the current server-authorized catalog. Assistants use their complete live definition without client-expanded controls. Recovery preserves accepted execution and identity; regeneration creates new admission. Project execution rechecks canonical authority, shared credentials, revocation and configuration drift through dispatch, tools, streaming and settlement.

Context follows active ancestors, never siblings; empty terminal-error pairs cannot duplicate unanswered questions, and partial answers remain. Budget within the model envelope, dropping whole prior turns; reject irreducible overflow before creation. Ordinary runs receive the server baseline plus Project instructions. Authenticated previews expose only that baseline and the visible-answer contract, never private context.

Personal presets supplement ordinary personal-chat baselines, including temporary/Memory-excluded chats. User-wide selection never enters Assistants/Projects. Assistants own their hidden user-level reminder after current content/attachments. Both blocks are irreducible, fenced at acceptance, frozen through preparation/recovery, and excluded from previews/utility prompts. Knowledge composition/repair uses accepted instructions; retrieval/review retains the original question. Instructions are not Memory facts.

Durable acceptance transfers execution to the server; HTTP disconnect does not cancel preparation or commands. Stop, deadlines and authority fences still apply. Recovery defers to a live owner and never replays ambiguous effects. PDF preparation precedes eligible Personal Memory; final admission revalidates authority/evidence and freezes dispatch state. No answer-provider/tool I/O occurs while preparing. Memory optional-signal loss cannot bypass authority. Temporary and Project runs bypass Memory; inbound Memory MCP is independent. [Memory](MEMORY.md) owns these boundaries.

Continuation summarizes active-branch text through the admitted System Model without tools, attachment contents or Workspace inspection. Enabled Workspace may copy `project/` unread into a private, single-use seed; names, bytes and findings never reach the model. Preserve ownership and retention scope, source data and conversation; never repeat interrupted provider work. [Frontend](FRONTEND.md) owns draft transfer. Title generation cannot overwrite user renames and attributes provider usage to its run.

Skills are immutable instructions, never tools or entitlement grants. Apply independently authorized Assistant-linked then manual selections, deduplicated in order. Freeze full revisions for recovery; deliver once as hidden, irreducible user context before the unchanged message, never system/developer authority or previews. They cannot activate tools or expand grants. Optional suggestions use authorized metadata and ordinary branch text, never hidden instructions. Selection is explicit; unavailable suggestions cannot block manual selection or Send.

Agent requires a personal manual Workspace turn. Codex owns planning, tools, compaction and completion; AIQSA owns admission, authority, accounting and settlement, without evaluator or context truncation. Resumes refresh paths, Skills and personal instructions at user authority; Codex retains system authority. Knowledge/Memory/images are unavailable. AIQSA Search exposes one query-only MCP tool, including with external MCP Off, alongside independently verified native search. Auto exposes external discovery/dispatch; All is explicit.

Off removes Agent time/call/token/output caps; accounting, leases, Stop and model/service constraints remain. Persist first terminal cause before revocation; no replay, extension or paid summary. MCP exhaustion permits remaining generation. Grants are independent of inbound OAuth; executor loss terminates, client disconnect does not.

## Search And Documents

Search freezes exact logical sources and hosted/query-only routes. Off, inheritance and explicit selection remain distinct. No source is silently dropped or substituted. Attachments do not disable selected Search: the query-only disclosure boundary in [Providers](PROVIDERS.md) prevents file data from entering client Search. Partial fan-out is explicit and findings remain untrusted data.

Chat PDF admission selects a verified route and freezes its destination before preparation. Required document work gates answer/Search/Knowledge/MCP dispatch and final context budgeting. The preparation model transcribes only; it does not become the answer model or create Knowledge. Local extraction carries a reading-quality caveat. An admitted Workspace run may survive classified transcription failure with its verified original and an explicit unread-content notice; access, integrity, cancellation and budget failures remain blocking. An accepted model route never silently falls back. Explicit retry creates a sibling, revalidates that route and may reuse compatible settled pages. Browser navigation does not own worker lifetime.

Knowledge ingestion follows its immutable Profile, exact document role and private local/original-page/image disclosure route. It does not borrow Memory's role or silently change destination. Crash-ambiguous dispatched work is never blindly replayed. Explicit Reprocess creates a new generation, preserving old attempts and reusing only checksum-verified settled work.

Transcription preserves visible text and meaningful visual information without inventing hidden values, causes or intent. Native PDF text may augment model structure only through the versioned safe alignment policy. Table relationships require structural evidence independent of cell text; uncertain rows, units and associations remain uncertain. Numeric normalization preserves exact decimal values and does not convert units or derive facts. Changes to parser/chunk policy create immutable profiles; ready artifacts change only through reprocessing. See [PDF output](../lib/server/parsing/modelPdfOutput.ts), [chunking](../lib/server/knowledge/chunking.ts) and [document context](../lib/server/knowledge/documentContext.ts).

## Knowledge Evidence

No scope means no Knowledge I/O. Freeze authorized Sources, immutable ready Versions/artifacts, Profile destinations and exclusions at admission; later membership/Profile changes cannot alter evidence. Ready subsets disclose exclusions; processing-only scopes fail before I/O. Capacity cannot silently narrow scope, nor equal content merge Source authority.

Admission selects full-corpus delivery when it fits the exact provider envelope, otherwise bounded `search_knowledge({ query, sourceAliases })` in the ordinary tool loop. Aliases are run-local disclosures, not scope grants; later narrowing can use only previously disclosed Sources. Every call rechecks scope, egress, projection readiness and frozen budgets before external work. Internal source-reading/discovery helpers do not become answer-model tools. Historical focused protocols remain recovery-only.

OpenSearch provides candidate identities and scores within immutable scope; PostgreSQL revalidates authority. A required lexical projection or backend failure fails visibly rather than becoming empty evidence or a silent dense-only/PostgreSQL fallback. Classified query-embedding unavailability degrades only that lane. No relevant evidence, unavailable retrieval, cancellation and invalid answer output remain distinct outcomes. Settled unavailability receipts replay without external I/O. [searchFailure.ts](../lib/server/knowledge/searchFailure.ts) and [searchProjection.ts](../lib/server/knowledge/searchProjection.ts) own failure and repair.

Retrieval combines independently eligible signals; weak proximity alone is insufficient. Source/Version/artifact/passage provenance defines occurrence identity, not content or membership. Diversity changes ordering only. Optional same-Source context stays labelled and cannot displace primary evidence. Omit over-budget exact excerpts whole with a reason. Rewrites retain the original question and constraints; search/packing policies stay independently frozen. See [retrieval core](../lib/server/knowledge/prismaRetrievalCore.ts) and [occurrence identity](../lib/server/knowledge/evidenceOccurrence.ts).

Optional relevance checks reduce unrelated context, without promising speedup or replacing ranking. Only complete cohorts may filter; partial/absent/failed checks preserve baseline. Exact/full-corpus reads bypass them. Freeze destination or absence at acceptance, enforce revocation and reuse settled receipts/usage. Default adoption requires consumer qualification and preserves administrator choices.

Both routes require Source-bound evidence and independent review of the original request, delivered evidence and candidate blocks. Composition cannot declare sufficiency; matching citations are not proof. Code derives coverage from supported requirements and enforces reference integrity, not semantic truth. Useful partial facts and valid derivations survive incomplete coverage. Exhaustive requests remain exhaustive; unavailable resources or missing premises prevent claims of completeness or corpus-wide absence.

Search-driven revision requires new delivered evidence; factual correction requires an explicit bound critique. Further retrieval preserves previously supported content and the delivered premises of a requested correction. Unchanged drafts/evidence do not receive repeated paid review, and failed optional correction preserves the latest verified partial answer and incurred usage. Structural repair uses unchanged authority inputs and a bounded rejection hint, never rejected provider content. Accepted prompts, schemas, reasoning policies and bindings remain frozen. Recovery decodes the accepted protocol, reuses settled operations and never applies current defaults to historical runs. See [review](../lib/server/knowledge/evidenceAnswerReviewV2.ts), [execution](../lib/server/knowledge/evidenceAnswerExecutionV1.ts) and [replay](../lib/server/knowledge/evidenceAnswerReplayV1.ts).

Publication is deterministic and provider-free. It revalidates exact excerpts and citation handles against the accepted manifest. Tool-result citations require completed persisted results and proof of delivery before synthesis. Pending, unknown, failed or undispatched evidence cannot support citations. Grounded token deltas remain private until settlement; internal wrappers and status lines never become answer prose. Source deletion preserves generated text but scrubs private evidence and later citation resolution. Engine improvements require general mechanisms and neutral regressions; benchmark answers and case identities never become product rules or ordinary test expectations.

## MCP And Workspace

MCP Auto, Load all and Off require explicit user action. Auto freezes authorized capabilities and the exact System Model at admission. An independently admitted optional route may select one sufficient capability; uncertainty/unavailability retains the full admitted System Model route. Neither route may substitute destinations. Discovery fails closed without lexical fallback. Revalidate tool authority; durably checkpoint selection before exposing schemas and replay without rerouting. Unrelated unavailable servers are not dependencies; Load all and Assistant allowlists are exact dependencies. Persist batches before execution, return results in provider order and enforce accepted call/round/context budgets. Exhaustion disables tools for final synthesis and displays the limit.

Workspace is an optional capability in that same tool loop. Admission freezes ready runtime/image, official catalog, network mode, paths and authority. The server injects sandbox identity; the model cannot select VM lifecycle, host-copy or network authority. Guest inputs are run-visible verified originals and, for personal chats, the user's saved Workspace secrets under the [Security](SECURITY.md) exception. Secret revisions are bound privately at acceptance and restored before execution; later settings edits cannot retarget an accepted run. Execution ownership and export leases remain exclusive to one run per chat.

A durably published answer may accept one waiting successor with frozen intent and configuration. The successor acquires no Workspace authority and performs no Memory, provider or tool work before its predecessor's handoff settles. Waiting survives browser loss and is bounded and cancellable independently of the predecessor. Revoked execution authority still permits a current worker to settle rejected work. Published text and reported accounting are immutable checkpoints; recovery completes outstanding handoff without replaying the answer or charging it again.

Every terminal path retires guest execution authority: registered processes stop, and unproven or crash-ambiguous execution stops the VM with its disk intact. Stop preserves the environment; successful turns leave no background process. Settled calls replay, ambiguous mutations do not. Completion requires a closed durable output obligation and retired guest authority; private-object transfer continues independently and idempotently. Export failure does not undo the answer, but path escape, symlinks, special files and bounds violations fail closed. Recovery discovers protected outputs without replaying commands or provider requests. Browser activity is a bounded safe projection, never raw runtime state.

## Settlement And Outputs

Provider-specific terminal proof is required for completion. Failure, truncation, timeout and cancellation preserve accepted partial text and reported usage where available without contradictory success. Guarded transactional settlement has one winner. Cancellation stops later work and durable stream writes promptly; stale reconciliation cannot sweep newer live runs. Recovery uses exact accepted checkpoints and bindings, never browser truth, reconstructed provider prose or repeated ambiguous side effects.

Client streams expose lifecycle, answer text, semantic activity, safe sources/outputs, actionable errors and usage. They exclude raw arguments/results, provider parameters, private retrieval evidence, internal identifiers and receipts. Project members share the same safe chat projection; Project event streams carry authorized invalidations, require resync for expired cursors and close on access loss. Context visibility estimates the current envelope, not cumulative billing.

Accounting uses provider-reported categories with exact stage/model attribution. Missing usage or price stays null; recovery enriches the same outcome without double counting. Shares use [Backend](BACKEND.md)'s positive snapshot schema. Gemini-grounded answer text survives ordinary settlement and sharing, while Suggestions, citations and structured artifacts stay private; discarded legacy answers cannot be reconstructed and unfinished legacy work must be fenced before removing replay-critical provenance.

Chat-title generation is optional application-owned work after the first successful personal-chat answer. Its provider latency never holds answer completion or the response stream open. Admission freezes a bounded excerpt and the selected destination; dispatched work is never replayed after an ambiguous interruption. Manual renames and chat lifecycle changes fence application of the result. Provider-reported title usage remains attributed to its source run independently of whether the title is applied.

Retain only evidence consumed by execution, recovery, side-effect safety, security, deletion, citations, outputs or accounting. [Providers](PROVIDERS.md) owns transport proof and [Persistence](PERSISTENCE.md) durable mechanics.
