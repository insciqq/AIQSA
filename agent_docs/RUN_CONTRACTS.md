# RUN CONTRACTS

Owner: Run pipeline maintainers
Scope: Provider-neutral admission, context, tools, Search/Knowledge, streaming, recovery, output, usage, sharing, and retention.

## Meaning And Admission

A run starts from one user message on a message-DAG branch, may use Memory, Knowledge, Search, and MCP, and produces a visible answer plus safe citations or generated outputs. Search is optional; internal execution evidence is not the product. Provider/model, Assistant, Search/Knowledge plans, tools, attachments, and controls come from the current server-filtered catalog and are revalidated before acceptance.

Ordinary runs receive the server-rendered standard-chat baseline and visible-answer developer rule. Assistant runs resolve one currently authorized immutable revision and reject client-expanded controls. Assistants grant no dependency entitlement and unavailable governed dependencies fail closed. Accepted requests freeze exact non-secret configuration and dependency bindings, including the installation's positive-integer maximum tool-call, tool-round, MCP Auto discovery-result, and MCP Auto discovery-timeout budgets; later edits affect future messages only. Installation defaults are 20 calls, 8 rounds, 10 tools per discovery, and 60 seconds across one discovery's routing attempts. Administrators may choose larger safe call/round integers without an arbitrary product cap, while one discovery cannot exceed the general 128-tool MCP run-plan boundary or the 120-second interactive discovery boundary; execution or recovery keeps the values accepted with that run.

Project runs receive the same standard-chat baseline plus the Project's current instructions. Project Memory is dormant in Personal Memory v1: admission creates no Project or Personal Memory bindings/items and injects no Memory context. A current Contributor, Manager, or Owner may invoke only the model, Assistant revision, Search, Knowledge, Skill, and shared/no-auth MCP resources in the canonical active Project set; Viewer cannot mutate chats or start runs. Project authority deliberately replaces per-initiator personal entitlement intersection and never expands a personal catalog. Models and Search resolve only installation/shared credentials, Knowledge uses its Project-safe shared embedding authority, and MCP uses shared/no-auth values even when a member has personal overrides. Personal credentials, Memory/history tools, unpublished Skills, OAuth identity, and personal MCP values are excluded, with no fallback or substitution. Admission binds the exact Project access, instructions, policy, resource revisions, and shared credential evidence; execution rechecks accepted access and covered authority before provider I/O, during streaming, before external tools, and before terminal settlement, so revocation or configuration drift stops the run.

The server, never the browser, builds ordered context from the active ancestor path. Siblings are excluded. Empty terminal-error pairs are omitted from later provider replay so retry does not duplicate an unanswered question; accepted partial-answer questions remain. Attachment-only turns use neutral private-data-free markers in replay. Eligible Personal Memory, prompts, attachments, tool transcripts, and current content all count toward one model-specific budget; prior turns are dropped whole, while an irreducible current request fails before run creation.

The first text send in a blank chat derives its bounded title locally inside the run-creation transaction, compare-and-set against only placeholder titles. A blank Project workspace remains client-local until that first send atomically creates the shared chat, user message, and admitted run; failure leaves no empty shared chat. Title creation never calls a provider or creates usage, attachment-only input keeps the placeholder, and shares copy the already-persisted sanitized title.

Admission has two commits only when an eligible Normal personal run may perform Memory utility I/O. Phase A accepts the exact message graph, ordinary bindings, private `preparing` run, bounded base request, and one content-bounded retrieval attempt. Phase B revalidates mutable authority and selected evidence, creates immutable Memory bindings/items, freezes the minimum recovery checkpoint, and makes the run dispatchable. Independent Memory ranking-signal loss may freeze a non-empty `DEGRADED` attempt with its reason, but no degradation bypasses selected-item authority rejoin; its client-safe presentation says Memory was used with limitations, while a fail-safe attempt with no admitted Memory says Memory was unavailable. An empty or rejected set remains non-visible Memory. Temporary and Project runs bypass Personal Memory storage and utility work entirely. No answer provider or tool I/O occurs while `preparing`.

## Search, Knowledge, And MCP

Search is an explicit ordered logical plan. Off, organization inheritance, personal preference, and concrete selected sources remain distinct. Admission assigns one complete deterministic set of exact hosted/query-only routes; it never drops a source or substitutes another connection/model/key. Hosted and client Search remain different disclosure/retention boundaries.

Client Search receives one normalized bounded generated query and server-owned controls, never transcript, prompts, attachments, or original file data. Fan-out merges safe normalized findings deterministically, preserves attributable partial failures, and calls no fallback. Search provider text is only a bounded tool result; Sources/citations are revalidated safe projections.

Attachments do not disable or narrow a selected Search plan. The query-only request shape, rather than a disclosure-consent gate, prevents attachment identity, names, bytes, and extracted text from reaching client Search.

Runtime admission, not browser state or declared model metadata, freezes whether the selected deployment has current credential-scoped Direct PDF evidence. On that route a PDF may be processing or have a local parser failure: the original verified object is sent without extracted text. Without that evidence, the same PDF requires ready non-empty local extraction and no original bytes are read for the answer provider. Missing records and storage, size, checksum, count, or payload-limit failures reject the whole attachment set before provider I/O. Route selection is final for the run; a failed direct provider request never causes an automatic local-parser retry or second answer request.

Knowledge ingestion independently follows the immutable Profile revision bound to its artifact. Local keeps PDF bytes inside the parser boundary; System Model Direct sends bounded original page ranges; System Model Vision sends bounded rendered page images. Model routes use the exact pinned installation role, no Search or tools, a fixed page-marker transcription contract, and provider-reported usage accounting. They do not require Structured Output or silently change route. The current model-PDF profile preserves the complete textual transcription and additionally projects information-bearing charts, plots, diagrams, maps, and figures into bounded searchable text: visible axes, legends, labels, units, series, readable points, and visually evident ranges or trends are retained, while hidden values, causes, and intent may not be inferred. Pure decoration creates no projection. A versioned Vision parser profile may combine the model-authored structure with clean visible native PDF rows from the same immutable original: exact matches contribute coordinates, materially novel non-conflicting rows may fill uncovered regions, and a clean row may replace exactly one aligned non-table Vision paragraph when their normalized token sequences differ only in numeric tokens. The native row must be on the same safe visible page; ambiguous, structurally different, invisible, invalid, or clip-only text remains ineligible, and the complete native change is rejected rather than truncated when a bound would be exceeded. Vision remains the structure owner while clean uniquely aligned embedded PDF text is the value authority. This local native-text lane is neither OCR nor a second provider route. A crash-ambiguous dispatched batch is terminal within its processing generation and is never blindly replayed by recovery. Explicit operator Reprocess advances the failed artifact to a new generation, preserves the old ambiguous attempt, reuses checksum-verified settled batches from older generations, and may dispatch one new bounded attempt for each still-unsettled batch. Geometry-proven repeated page furniture is deduplicated for retrieval, but one canonical source occurrence remains chunkable so a report header cannot erase document-level facts merely by appearing on every page.

Table structure requires evidence independent of cell text patterns. Repeated labels, blank values or apparent missing leading tabs cannot create PDF row spans or shift columns; explicit valid layout markers retain their authority. A textual first row followed by numbers alone cannot turn a form into a headed table. Unresolved associations retain their raw rows, units and uncertainty. Parser and chunk policy changes create new immutable profiles; existing ready artifacts change only through an explicitly requested reprocessing lifecycle. The executable owners are [PDF transcription](../lib/server/parsing/modelPdfOutput.ts) and [chunk projection](../lib/server/knowledge/chunking.ts).

Numeric observation normalization preserves exact decimal strings within fixed input/exponent/output bounds, including scientific notation. Raw values, units and ambiguity remain separate; normalization neither converts units nor derives facts. Values outside the supported exact format remain explicitly ambiguous and cannot become rounded numbers or underflowed zero. Historical artifact values are decoded without renormalization; [document context](../lib/server/knowledge/documentContext.ts) owns the versioned normalization boundary.

With no selected Knowledge scope, the run performs zero Knowledge operations. Otherwise admission binds exact Bases or directly selected Sources, immutable ready Source Versions/artifacts, the active embedding destinations, and authority. `All my knowledge` resolves through the same owner-scoped rules; Project use requires explicit Project bindings, and Assistant selection grants no additional entitlement. Later membership, replacement, Profile, or Trash changes cannot alter accepted evidence. A usable partial parse remains ready evidence with safe warnings. Admission skips a processing-only Profile when another selected Profile is ready; zero ready selected Sources yields `sources_processing` before embedding, retrieval, or answer-provider I/O, while a ready subset proceeds with immutable exclusions and yields `partial_sources_ready`.

Knowledge answer admission freezes the installation answer policy and one route for the run. When the canonical ready corpus is estimated at no more than 70% of the selected model context and the exact final provider request still fits, every admitted passage is supplied as one full-corpus Evidence Manifest: there is no Knowledge tool, query embedding, or retrieval operation, and answer-model tool calling is not required. Otherwise the run exposes exactly one strict tool, `search_knowledge({ query, sourceAliases })`; its schema has no scope IDs, limits, modes, or hidden controls, `query` is normalized non-empty Unicode of at most 3,000 code points, and `sourceAliases` is a unique list of run-local `S…` aliases. The first call uses an empty list. A later call may narrow only to aliases that earlier completed results in the same run already disclosed; aliases are re-resolved against immutable admitted Sources and never grant authority. A whole-Base scope larger than the bounded eager Source-binding set remains authorized in full through its immutable admitted Base snapshot; only Sources selected into bounded evidence receive stable run-local aliases before provider packaging, and this disclosure-bound persistence is neither corpus sampling nor a retrieval scope reduction. The answer model may call the tool within the frozen installation maximum, 12 by default and admin-configurable from 1 through 32 for future runs. Each accepted call is preflighted before external I/O, rechecks current scope authority and Memory egress policy, and has a bounded execution envelope across query embedding, hybrid retrieval, hosted reranking, and durable receipt settlement. A local Knowledge deadline is persisted as a technical error result so the provider may continue from earlier evidence; user cancellation remains fail-closed and never becomes such a result. The operation, embedding, candidate, retrieved-text, cost, and latency ceilings scale together from that immutable snapshot; the next call beyond it is rejected before embedding or retrieval.

Processed Source artifacts and ready search projections are separate states. A required projection failure stops retrieval; successful search with no evidence, unavailable projection, backend failure and later invalid answer output remain distinct through tool settlement and recovery. Existing run/tool identities correlate safe reason, stage, index contract versions and an optional hash of the accepted scope; private bodies, queries and credentials do not become diagnostics. Repair must preserve the exact canonical artifact/fingerprint and readiness fences, with no silent dense-only fallback. The failure and repair owners are [searchFailure.ts](../lib/server/knowledge/searchFailure.ts) and [searchProjection.ts](../lib/server/knowledge/searchProjection.ts).

Selection capacities may differ by mode, but capacity never silently changes the requested scope. Admission must reject an oversized explicit selection or retain counted exclusions; large whole-Base selection keeps its immutable disclosed binding route. Excluded resources and failed retrieval operations remain explicit limitations in the accepted manifest, publication and recovery. Useful facts may still be published, but an answer over that limited evidence cannot claim complete coverage or establish absence throughout the requested corpus. Even a zero-evidence response retains known exclusions. The admission and persistence boundaries are [runAdmission.ts](../lib/server/knowledge/runAdmission.ts) and [prismaRepositoryBindings.ts](../lib/server/runs/prismaRepositoryBindings.ts).

Both routes settle through the same Source-bound Evidence Manifest and citation authority. New answers use coherent composition followed by independent evidence review. Composition preserves useful partial facts, executable code and valid derivations; it cannot declare its own answer sufficient. Review sees the exact original request, delivered evidence and candidate blocks, checks factual premises and requested conditions, and selects only supported blocks with their exact source handles. Relevance or a matching citation is not proof. Review maps essential request requirements to supported blocks; the server derives coverage from that map instead of accepting a separate sufficiency label. A missing premise can justify ordinary search, while an omitted or incorrect result with existing bound premises can justify a factual correction. A rejection must name the factual issue. These model judgments remain fallible; the server owns reference integrity, source authority, bounds and deterministic publication, not semantic truth. [evidenceAnswerReviewV2.ts](../lib/server/knowledge/evidenceAnswerReviewV2.ts) owns this review contract.

For RAG answers, accepted gaps may drive further ordinary search batches within the frozen search, tool and answer-operation budgets. Continuing requires remaining gaps and room to compose and review another answer. A search-driven revision requires newly delivered evidence and retains the source bindings of previously supported content; repeated receipts alone are not new evidence. An explicitly identified correction may instead reuse its bound evidence once per manifest. An unchanged draft over unchanged evidence receives no repeated semantic review. A failed or still-empty optional correction preserves the latest verified partial answer, including all incurred usage. The admitted workflow freezes these continuation semantics for recovery, which reuses settled tool calls and exact accepted manifests without repeating ambiguous I/O. Historical review protocols remain unchanged. [evidenceAnswerExecutionV1.ts](../lib/server/knowledge/evidenceAnswerExecutionV1.ts) owns execution; [evidenceAnswerV1.ts](../lib/server/knowledge/evidenceAnswerV1.ts) owns shared draft validation and publication.

An explicit all/every/list request, named participants or separately requested outcomes remain exhaustive. A why/how answer requires an evidence-supported explanatory relationship, and a procedure must satisfy the requested result and conditions. Arithmetic and applying documented operations are valid when all premises are supported. Dates, labels, values, units, conditions, polarity, attribution and epistemic force stay bound to the actual object and Source. A known operand remains useful when another operand is missing. Missing requirements, incomplete analysis and unavailable selected resources prevent complete coverage; capacity never silently reduces the user's request. Independent Sources with equal text retain their own citation authority.

Exact retrieved excerpts are never shortened. Optional expanded context may be omitted as one explicitly labelled field; an exact excerpt that still does not fit is excluded with its budget reason before provider I/O. Structural locators preserve table headers, empty cells and occurrence identity. Provider-facing labels do not establish source order or provenance. The same retained evidence is supplied once to each answer operation. Paragraph text is escaped as literal data, code retains its exact punctuation and whitespace, and source citations are rendered outside code blocks.

Accepted operations freeze the request, evidence, schema, prompt, reasoning policy and provider binding. Each stage permits one fresh structural repair using the unchanged authority inputs and a closed rejection code. Transport failure or unexplained semantic disagreement does not authorize a repeated paid request; a factual correction requires the bound critique described above. Rejected provider payloads are not persisted. Publication replays settled accepted records through the production validator, rechecks every excerpt against authorized delivered evidence and cannot call a provider. Content-free receipts distinguish answer-block counts from historical claim/Scope counters; these counts are operational observations, not a truth score. [evidenceAnswerReplayV1.ts](../lib/server/knowledge/evidenceAnswerReplayV1.ts) and [evidenceRepository.ts](../lib/server/knowledge/evidenceRepository.ts) own replay and authorization.

Historical Scope/contribution runs retain their exact accepted protocol, decoders and recovery behavior. Their independent request decomposition, append-only pending requirements, additive correction and eight-operation bound are owned by [answerGroundingExecutionV40.ts](../lib/server/knowledge/answerGroundingExecutionV40.ts), [answerGroundingSelectorV22.ts](../lib/server/knowledge/answerGroundingSelectorV22.ts) and [answerGroundingReplayV40.ts](../lib/server/knowledge/answerGroundingReplayV40.ts); current defaults never reinterpret accepted turns.

Engine changes must address general retrieval or answering mechanisms and have independent neutral regression evidence. Benchmark queries, labels, reference answers and case identities never enter product rules or ordinary tests. Judge disagreement alone is not proof of a deterministic product defect.

Provider-native wrappers such as `citeK1K2` are accepted only inside the model-to-server evidence protocol and only when every handle belongs to the final manifest; malformed or unknown handles fail closed. They are never copied from Draft claim text into the public answer. Knowledge token deltas are withheld until grounded settlement completes, so internal status lines, hidden operations, and provider citation wrappers never become visible answer prose. A rendered citation opens the existing authenticated Source rail at the exact accepted version and page; when retained PDF coordinates exist, a bounded private page render highlights them, otherwise the original page and normalized excerpt remain the fallback.

Each automatic call attempts one query embedding across every compatible admitted Profile and performs one hybrid repository operation. Candidate generation uses passage-level BM25 and dense retrieval plus authoritative exact and metadata matches. Hierarchical text enriches selected passages through bounded same-Source context; independently ranking duplicate document and section representations across the corpus adds correlated votes and work that grows with broad lexical matches. [prismaRetrievalCore.ts](../lib/server/knowledge/prismaRetrievalCore.ts) owns candidate retrieval and context expansion. OpenSearch applies owner and immutable artifact scope before top-K, returns identities and scores only, and PostgreSQL revalidates every candidate. Missing, stale, unavailable, malformed, or incompletely revalidated OpenSearch evidence fails the Knowledge operation visibly; no PostgreSQL passage-lexical fallback or legacy ranking receipt is selected. A classified query-embedding-only timeout, connection/rate-limit/provider outage, or unavailable embedding configuration disables only the semantic lane, records bounded degraded evidence, and continues the remaining authoritative and BM25 lanes; PostgreSQL, OpenSearch, authority, SQL, invariant, and unrelated failures remain visible failures. Candidate signals must pass their named lane-specific relevance eligibility before deterministic fusion. Exact equality remains eligible, but its ranking priority reflects how discriminating the matched values are within the accepted scope; common example literals must not reserve most of the candidate pool ahead of passage relevance. A weak nearest vector alone never enters answer context. Canonical Source and immutable occurrence deduplication precede deterministic soft diversity: a close alternative Source may be promoted, but one clearly stronger Source may fill all sixteen broad-map primary slots from the bounded canonical pool. A later automatic search may reduce to Sources disclosed by earlier evidence and then returns at most eight primary slots. Every later search uses bounded, versioned occurrence history reconstructed from accepted results before final ranking and same-Source context expansion. Identity is the immutable Source/Version/artifact/passage tuple, not text equality or Base membership: identical text in another Source, Version or row remains independently addressable, while another delivery of the same occurrence is suppressed. The ranking profile pins this policy; historical receipts remain immutable. Earlier handles remain available in the provider conversation. [evidenceOccurrence.ts](../lib/server/knowledge/evidenceOccurrence.ts) and [retrievalRanking.ts](../lib/server/knowledge/retrievalRanking.ts) own identity and selection. An unstructured primary may carry at most one previous and one next same-Source block. A complete table-row primary may instead carry a bounded set of complete nearby rows and independently relevance-eligible complete rows or body passages from the exact same immutable Source; these secondary segments never become primary results, never introduce another Source, remain individually atomic, and are omitted whole rather than truncated when the provider evidence budget cannot fit them. When no candidate remains eligible, `no_relevant_evidence` is a completed bounded tool result that explicitly forbids inventing a Knowledge answer; the answer model continues normally.

Each provider-visible Knowledge result contains Source-bound blocks with answer-scoped `[K…]` handles, safe Source labels, exact immutable Source Version/artifact bindings, locators, primary excerpts, and any clearly separated same-Source neighbor context. Source content is untrusted data, never instructions, and the result explicitly states that it is not proof of exhaustive corpus coverage. A cited handle is valid only when a completed persisted `search_knowledge` call has exact stored provider text and the provider-running checkpoint proves that result was delivered before synthesis; deleted, malformed, unknown, failed, pending, or later undispatched handles fail closed. Before answer synthesis, a new tool-loop run packs the best remaining rank from each completed search operation before advancing to the next result rank, then applies the immutable provider-evidence byte/token budget. This bounded rank interleaving prevents an early broad query from consuming the entire final manifest while preserving each retrieval operation's own ranking; the selected policy is frozen in the accepted run and persisted manifest. Primary passages take priority over optional neighbor expansion, so background context cannot displace separately retrieved evidence. Previously reviewed evidence keeps its exact delivered form, including any expanded context supporting an accepted block. Historical accepted runs without that selector retain chronological operation-first packing during recovery. Headerless table rows remain association-ambiguous unless the immutable chunk profile proves one complete bounded inline label/value pair from exactly two cells in a singleton table or two structurally separated cells; adjacent multi-row pairs, multi-value rows, projections, and lexical proximity alone do not acquire that authority. The deterministic renderer owns escaping, citation placement, answer order, and the fixed partial-coverage or insufficiency note; the server never derives a missing semantic conclusion from literal operands.

`read_source`, `find_exact`, and `discover_sources` remain internal deterministic services and historical-recovery artifacts, never answer-model tools. Generic recovery replays settled tool results from their durable checkpoints, reauthorizes an unsettled Knowledge call before dispatch, and never repeats a settled or crash-ambiguous external side effect. Historical focused Knowledge runs retain their original request, manifest, status-line, citation, and recovery decoder; new admission never creates that path. Permanent Source or Base deletion preserves generated answer text but scrubs private evidence and provider payload to safe tombstone state, so later citation resolution exposes no private filename, excerpt, locator, or identity.

MCP extends the same tool loop. Ordinary runs choose Auto, Load all, or Off, and that mode changes only through an explicit user action. Auto freezes a private schema-free capability catalog, begins with only `find_tools(goal)`, and asks the exact admitted System Model for no more than the discovery-result limit accepted with that run. Its first provider round disables parallel tool calls; Load all and later rounds retain the admitted model's ordinary parallel behavior. If a provider still emits multiple valid `find_tools` calls in one round, the server combines them into one bounded routing operation, materializes one selection, and returns that same selection under every original call ID. Verified strict structured output decomposes the combined goal into distinct MCP outcomes and maps tools to each; a first pass that explicitly leaves an outcome uncovered receives at most one corrective routing request within the single accepted discovery deadline. Routing receives bounded branch/current text plus compact server/tool/argument summaries, excludes already loaded tools, has no lexical, regex, embedding, provider-native, or model fallback, and fails closed when an invoked route is unavailable or invalid; an Auto run that never calls `find_tools` has no System Model dependency. Selected IDs are revalidated against the frozen catalog and current materialization authority. The active subset grows monotonically under the ordinary MCP tool/schema/context bounds, with no separate discovery-wide tool cap. Every original selection call, including a coalesced or empty one, is checkpointed by persisted tool-call ID with exact runtime bindings before new schemas reach a provider; execution and recovery replay that checkpoint without rerouting. All successful routing usage, including a corrective request when made, is attributed to the same run separately from answer usage. Router failure exposes only `mcp_auto_discovery_unavailable`. An unrelated unavailable enabled server is not a run dependency. Load all and Assistant allowlists remain exact dependencies and fail closed when unavailable. Administrator policy is validated over the complete sanitized inventory and active revisions affect future admission only.

Internal strict-schema utility work uses the installation System Model through its exact admitted role and immutable credential lineage. A dependent feature may use it only when the current tuple carries verified structured-output evidence; absence, stale evidence, or an unsupported adapter is an explicit unavailable capability and never triggers provider or model fallback.

Memory semantic sorting may instead bind the independently selected installation reranker role. Its immutable snapshot is score-only and does not require Structured Output; ordinary candidate pools use one request unless the complete provider-neutral envelope requires a bounded split. Sorting is atomic across that logical pool: every batch must use the same governed snapshot and return exactly one valid score per candidate. Any missing, duplicate, unknown, invalid, failed, cancelled, or snapshot-mismatched result discards every semantic score and retains the complete fused RRF order; each failed or uncertain batch has at most one fresh retry inside the admitted deadline. The generative System Model sorter remains only the versioned compatibility path when no dedicated reranker is selected. A selected-but-broken reranker never falls through to that path, while the distinct global aggregation role remains strict generative System Model work. Reranker destinations and consent evidence are tracked separately from System Model and embedding destinations.

Skills are immutable text instructions selected manually or linked by ordered definition ID from an immutable Assistant revision; they are not executable tools. Assistant selection does not clear or lock manual Skills. Admission builds the effective list in Assistant order followed by manual selection order, removes repeated definition IDs without reordering, and binds each exact current revision. Ordinary runs resolve every remaining Skill through current user/group/installation authority; Project runs resolve only canonical active Project Skill publications and separately bound Assistant dependencies, never a member's personal Skills. The full effective text is rendered once into an exact hidden user-level context item immediately before the unchanged current user message; it never enters system/developer instructions or visible chat. That item is irreducible in the ordinary context budget, so prior turns and attachment text may yield first but Skill instructions are never truncated; an over-budget request fails before provider I/O. Adapters preserve the same ordering whether they emit adjacent user messages or merge them, while request previews replace the Skill text with a fixed omission marker. The accepted rendered item is persisted in normalized context and recovery reuses it without resolving live Skill state. An Assistant grants no Skill entitlement: every audience, including a Project, must receive compatible direct authority for every linked Skill. Removing a Project resource atomically removes dependent Project Assistants and their defaults rather than leaving a partial authority set. Skills do not auto-activate, execute code, load resources, or grant MCP authority; later edits and publication changes affect future admission only.

Requested tool batches are durably recorded before bounded execution and results return in provider order. Settled calls replay; crash-ambiguous external side effects do not. Every round re-applies the context, output, accepted call, and accepted round budgets. Reaching either tool budget disables further tool choice for final synthesis and produces a user-visible reached-limit warning; a model without tool capability explicitly runs with none rather than mutating persistent tool settings.

Search reformulations are retrieval hypotheses: they may name an underlying mechanism or missing step while preserving the user's actual constraints. A failed attempted approach is not itself a required solution. Retrieval instructions are pinned independently of answer-review revisions so upgrading the answer protocol cannot silently switch search behavior; recovery retains the instructions the historical policy actually selected. When the answer model rewrites an automatic Knowledge query, its single embedding batch and the lexical lanes retain the current-question anchor alongside the model query. The anchor is the complete normalized question when it fits; an overlong question contributes verbatim beginning and ending spans separated by an explicit omission marker inside the same bound. The full question remains unchanged for the answer, and the separately admitted anchor policy preserves historical execution/recovery. Semantic candidates from both inputs are deduplicated before ranking, so a rewrite cannot erase the independent original-question signal or gain weight merely by finding the same passage twice. Prior-result exclusion makes later calls advance through novel evidence, while any Source aliases remain the authoritative scope filter.

## Streaming, Recovery, And Settlement

Normalized SSE publishes live lifecycle, answer deltas, a bounded semantic tool-activity projection, safe sources/artifacts, actionable warnings/errors, usage, and terminal completion. Presentation-only synchronization stays transient. Text may stream per token, while durable partial text/checkpoints are batched. The visible assistant message contains the answer and may summarize tool name, server name, round, state, duration, and reached-limit warning; it never exposes request previews, Search traces, provider parameters, tool arguments/results, internal identifiers/errors, raw event timelines, or usage receipts.

Authenticated Project members may read the same client-safe persisted chat projection regardless of which member initiated a turn. That projection includes author attribution, durable partial answer text, normalized active/terminal lifecycle, semantic tool activity, and safe sources/artifacts; it does not broaden the SSE contract or expose private execution evidence.

An authenticated Project event stream carries ordered invalidations, not business mutations or private event payloads. Delivery reauthorizes current membership, projects current client-safe state from authoritative rows, replays retained cursors after reconnect, and requires a canonical resync when the cursor is too old. Access loss closes the stream and future Project reads remain privacy-neutral. Heartbeats preserve transport only and do not imply presence.

Only provider-specific terminal proof permits completion. Truncation, malformed or over-budget streams, timeout, cancellation, safety overflow, and provider failure keep accepted partial text and reported usage where available but never write a contradictory success. Terminal persistence and the status-gated winner occur transactionally; one writer wins completion/cancel/failure.

Recovery uses purpose-bound checkpoints, exact accepted context/bindings, settled tool results, and provider-native handles. It never reconstructs private truth from browser data or provider prose, repeats an ambiguous side effect, or converts a terminal safety/timeout outcome to success. Boot and route-triggered stale reconciliation use guarded age/status boundaries and cannot sweep a newer live run.

Cancellation stops later rounds and durable stream writes promptly. Provider timeout remains distinct from user cancellation. Public and client errors expose stable codes, concise actionable copy, and bounded counters only—never payloads, endpoints, credentials, reasoning, tool arguments, private retrieval text, or storage facts.

## Outputs, Usage, And Retention

Completed UI exposes answer text, safe inline citations and Sources when present, generated outputs, ordinary message actions, Branches, a compact tool-activity summary, and explicit feedback for approved mutations. Live UI exposes factual progress, Stop, recovery, Retry, and actionable failure. Reasoning may be shown only through its reviewed normalized output; internal traces are not inferred or reconstructed.

Usage derives only from provider-reported categories. Answer rounds, client Search, Knowledge embeddings, and Memory utilities retain their own exact provider/model attribution and then contribute to aggregate accounting where applicable. Missing failed-call usage and price are null, never estimated; cached/reasoning tokens are not inferred. Recovery replaces or monotonically enriches the same outcome instead of double counting.

Anonymous sharing snapshots the active visible branch through the positive sanitized schema in [Backend](BACKEND.md). A grounded Gemini live-only branch is not shareable because durable content does not exist. Branch checkout is history navigation, not a run-inspection surface.

Persist only what execution, recovery, side-effect safety, security, deletion/retention, citations/outputs, or aggregate accounting consumes. Logs remain structured and content-free. [Providers](PROVIDERS.md) owns wire terminals, [Memory](MEMORY.md) personal context, and [Persistence](PERSISTENCE.md) durable mechanics.
