# PERSISTENCE

Owner: Persistence maintainers
Scope: Durable ownership, migrations, retention, backup, restore, and deletion obligations.

## Authority And Shape

`prisma/schema.prisma`, committed migrations, database constraints, repositories, and stateful tests own exact tables and fields. Prose records only cross-aggregate rules. PostgreSQL is the coordination authority for users, entitlements, chats/message DAGs, immutable configuration revisions, accepted runs/bindings, jobs, usage, Memory, Knowledge, MCP, and share snapshots. The installation Knowledge Profile uses an optimistic active pointer over append-only, database-immutable revisions to authorize the embedding destination and PDF-processing route. A model-backed revision also pins the exact admitted System Model snapshot and policy version; generation rows retain their exact profile identity, and pointer changes affect future work without rewriting accepted bindings or existing generations. Private object bytes live in the configured S3-compatible store or filesystem fallback; relational rows own capability and lifecycle.

AIQSA disables PostgreSQL JIT for its latency-sensitive Prisma OLTP pool at connection startup; bounded vector-planner controls and other query-specific execution settings remain transaction-local.

Tenant-bearing parents and children prove the same owner at the database boundary wherever representable. Accepted revisions, bindings, content generations, and recovery evidence are immutable and restrictive while referenced. Mutable recommendations, preferences, and drafts grant no entitlement. Null, explicit Off, and a concrete choice remain distinct persisted states.

Knowledge Source identity is independent of Base membership. A canonical owner-scoped Source owns append-only immutable Source Versions; processing identity is reused per exact Source Version and immutable Knowledge Profile revision, and a ready artifact cannot be rewritten. Bases retain soft-removable membership history, while each accepted run binds an immutable Base snapshot containing the exact ready Source Version/artifact evidence available at admission. Membership, current-version, and profile changes create different future evidence and never rewrite an older snapshot. The V1 bridge uses explicit one-document/one-version mappings and never merges equal checksums; its application backfill is content-free, resumable, idempotent, and reports aggregate reconciliation only. Old V1 bindings remain readable through the nullable snapshot bridge.

Each model-backed PDF page batch has one durable request identity per artifact processing generation and a reserved, dispatched, settled, or ambiguous state. Recovery may reuse a checksum-verified settled transcription but never repeats dispatched work whose external outcome is unknown. Explicit operator Reprocess advances a failed parsing artifact to a new generation while preserving prior attempt lineage; exact settled batches remain reusable and only unresolved batches receive new attempt identities. Provider usage settles once against each attempt. Bounded transient transcription text exists only until the normalized artifact is durably advanced to chunking, then is cleared in the same transaction; Source/artifact purge removes the remaining attempt lineage.

One Knowledge retrieval session belongs to one model run and owns the accepted scope snapshot, answer-policy snapshot and route, processing exclusions, raw Source-bound evidence, citation contract, and cited handles. A full-context run writes every exact admitted passage as Source-bound evidence at acceptance and performs no retrieval operation; a RAG run creates evidence from completed `search_knowledge` calls, each with one generic `ModelRunToolCall` lifecycle row and one immutable `KnowledgeRun` receipt. Both routes fence the exact final Evidence Manifest and provider attempt before grounding. Bounded scopes persist their admitted Source bindings eagerly. A larger whole-Base scope instead persists exact immutable Base snapshots and materializes a Source binding only when bounded selected evidence discloses that Source; recovery reauthorizes the same Base snapshots plus every disclosed binding, without serializing the remaining corpus into an operation request. A directly selected or Project-bound Source can have zero Base provenance, while one Source reached through several Bases still has one alias and one exact Version/artifact identity; duplicate Base membership cannot create another vote. Stable answer-scoped handle ordinals never encode a Base, score, or operation. Installation answer-policy changes are optimistic and future-only; accepted runs never inherit a later search maximum or route decision.

Tool batches, preflight decisions, results, provider-running checkpoints, Knowledge usage, and Memory egress receipts are persisted for deterministic continuation and side-effect safety. Terminal settlement authorizes a cited Knowledge handle only from a completed call whose exact persisted provider text was delivered by the checkpoint before final synthesis. Historical focused sessions retain their immutable request, Evidence Dispatch Manifest, fenced answer attempt, structural status, and decoder for read/recovery compatibility; current admission never writes that shape. Internal `read_source`, `find_exact`, and `discover_sources` may keep only bounded purpose receipts required for authorization, deterministic replay, and deletion.

Automatic fact extraction settles success only with an owner-scoped strict decoded result that is already recoverable. Apply reauthorizes current source and settings, records content-free terminal outcomes per candidate, and clears the staged private packet only after all candidates are durable; infrastructure failure remains retryable and never authorizes provider replay or false job success. Unapplied packets have a bounded recovery window, and source/reset/account lifecycle clears them before protected parents or execution authority are detached.

Memory context-derived semantics retain immutable owner-consistent source dependencies rather than copying antecedent text into evidence. Message dependencies bind the exact source identity, safe projection version, content hash, and edit snapshot; they may reference a direct-user message or a visible assistant message with exactly one completed run linked to its parent user turn and, when selected, an active owner-scoped Assistant definition. Such a dependency can reauthorize contextual interpretation but never becomes fact evidence or testimony. Fact dependencies are acyclic and bounded to two edges. A required invalid dependency is an immediate read-time fence, including before deferred purge removes its source; an identity move retains its still-valid historical source as provenance rather than treating the move's own retraction as source loss. Fact moves resolve through one owner-scoped, bounded database function: only RETRACTED intermediates ending at one ACTIVE root are reusable, while missing, cyclic, over-depth, conflicted, or terminal chains return no authority. Historical projections key semantic states by that root plus structured value and domain-time identity rather than by representation/version identity. Entity-backed product facts bind an owner-consistent canonical `subjectEntityId`; PostgreSQL enforces the `slot:v3` subject/key shape and terminal `MERGED`/`RETRACTED` entity topology. Versioned identity cutover retains immutable legacy and Unicode canonical keys and records only their SHA-256 compatibility pairs; collision/preflight diagnostics are aggregate and content-free, and account deletion cascades the ledger. Entities, aliases, alias supports, fact-version links, merge/move traces, and relation resolver receipts remain owner-consistent; one source-valid support predicate fences every alias consumer before purge, automatic aliases cannot outlive their final physical support, and account/reusable-source deletion removes these derivatives before their protected parents.

Active incremental history chunks and current chat digests are derived state authorized by exact owner/chat source maps and the current checkpoint path. Stable-chunk creation counters remain audit identity; checkpoint-first reuse re-proves every mapped message's edit snapshot, admission, and active-DAG membership before content loading. Pending mutations preserve the last successful pipeline version, and destructive source-context drift writes a distinct rebuild-required marker until a successful full apply replaces it. A v2 digest persists its complete bounded eligible chunk/message coverage, final anchor, source and input fingerprints, rebuild-policy version, update mode, and incremental depth even though each provider request sees only a bounded Safety-Lite-projected delta or hierarchical segment. An unchanged fingerprint may reuse only previously Safety-Lite-safe digest content; periodic depth and any non-prefix change force a full hierarchical rebuild. Optional digest failure cannot block the raw lexical history projection. Deferred database guards prevent active chunks or digests from losing required maps, while retrieval and frozen-run rejoin independently repeat the source proof before use.

Dream synthesis stages one strict provider result only behind its succeeded job execution binding, then clears the private decoded output and source bindings atomically with semantic apply. The durable result is an immutable depth-one PATTERN version plus exact owner-consistent source relations; per-pattern ingestion identity and source-set identity prevent replay from creating copies. Pattern current pointers are valid only for proposition facts with at least three relations. Direct source authority and each relation's captured eligibility hash are re-proved inside commit and every later reusable read. Incremental indexing and full rebuild persist the same deterministic relation provenance shape, while invalidation retracts the derived pointer before one idempotent targeted replacement job can be admitted. Derived-pattern retraction preserves relations and execution audit until the ordinary retention purge. Reset/account deletion cancels work and clears or removes any unapplied staging payload before completion.

Decay access state adds no separate event ledger. A frozen run binding may contain a given fact version only once, and that exact run item owns an immutable policy-versioned touch marker. The marker and owning fact update commit together, so concurrent finalization recovery cannot count the same binding/version twice and an ineligible or failed fact update retains no marker. Existing fact `lastUsedAt` and temperature state retain at most twenty uses; they never mutate a version's semantic state, validity interval, or expiration, and run dispatch remains independent of best-effort touch settlement.

Permanent Knowledge purge is the sole mutation capability for accepted private retrieval state. In one guarded lifecycle it clears identities, labels, excerpts, boundaries, locators, request content, raw evidence, manifest payload, and private provider payload while preserving only content-free accounting and safe tombstone state. Ordinary API and log projections never include Knowledge queries, private provenance, evidence text, manifest bytes, tool results, or provider payload. Retired focused or multi-step storage may remain only when historical accepted records require inert read compatibility; current runs never write it, and forward cleanup removes it when evidence, citations, recovery, and deletion no longer depend on it.

Personal and Project ownership are disjoint principals. A Project child is owned through `projectId`, never through the member who created or uploaded it, so account deletion removes that member's grants without deleting the shared aggregate or abandoning attachment processing. Mutable actor references may become null while bounded display-name/role snapshots preserve authorship and audit meaning. Canonical Project model/Search/MCP bindings and Knowledge/Assistant/Skill publications are scoped authorities distinct from personal grants; accepted Project run bindings preserve the initiating identity, exact access, instructions, policy, resource revisions, and installation/shared credential evidence needed for recovery. The nullable recovery-authority fields added to historical Project bindings cannot be derived reliably from older accepted state: new bindings must populate them, active incomplete legacy bindings settle fail-closed without provider I/O, and terminal historical rows remain readable. Project Memory data remains dormant and unchanged in Personal Memory v1, and current Project admission creates no new Memory run bindings. Database constraints and deferred triggers enforce owner/source consistency and at least one direct active Owner, including concurrent grant changes.

Skill definitions own immutable text revisions plus group/installation publications. Publications are live grants on the definition: future discovery and admission resolve the current revision, while every accepted run binds the exact revision it received. Immutable Assistant revisions may own ordered relational links to Skill definitions, never to Skill revisions; this keeps the Assistant list stable while future runs receive each Skill's current text. An Assistant publication is valid only when every linked Skill directly reaches the same audience, and removing a Skill publication is blocked when no remaining publication covers an affected published Assistant audience. Deleting a Skill tombstones the definition and transactionally removes its publications and all Assistant links without deleting revisions or accepted bindings; recovery of a finally accepted run does not recheck current publication or tombstone state. A publication never grants executable or MCP authority. Auto MCP discovery similarly freezes its schema-free catalog and monotonic discovery epochs inside the accepted recovery request while exact materialized server generations remain relational run bindings. Each epoch is identified by its persisted `ModelRunToolCall`, including an empty selection, so equal goals remain independent calls and recovery never uses goal text as an idempotency key.

The protected non-archived `Full access` group has explicit membership and semantically receives every current/future active provider connection, answer model, and Search source without materialized ordinary grants. Its name and lifecycle are immutable. MCP use remains materialized per server so deletion and revision policy retain exact relations; it never grants personal slots, OAuth identity, or personal secrets. Ordinary grants require exactly one principal and one nonempty target.

Persist run or tool data only for execution, recovery, duplicate-side-effect prevention, security, deletion, citations/generated output, retention, or aggregate accounting. Presentation-only event histories, previews, and inspector payloads are not storage justification. Remove a projection first, prove recovery consumers, stop writes, then remove schema with a forward migration.

Project synchronization uses a bounded durable outbox inserted with the authoritative mutation. Its monotonic opaque cursor, Project identity, event category, affected identity/version, and timestamp support ordering and reconnect; rows contain no secret, attachment content, private resource label, retrieval text, tool arguments/results, or browser projection. Current safe state is serialized from authoritative tables at delivery. PostgreSQL notification is only a post-commit wake-up signal, never the durable source, and retention expiry produces an explicit canonical resync.

## Migrations And Bootstrap

`20260815000000_baseline` is the immutable first migration anchor; its reviewed custom PostgreSQL DDL is part of the contract and cannot be reconstructed from Prisma alone. Future changes are append-only migrations. Persistent installations use `prisma migrate deploy`, never `prisma db push`.

Personal Memory retrieval cutover is content-free: inventory and backfill compare bounded owner-scoped item identities, hashes, safety/source/suppression snapshots, and aggregate counts without reading source text into an operator surface. A shadow generation is the only switch unit; activation advances the Memory fence and the prior generation remains immutable and superseded. Rollback is allowed only when the retained generation's exact entry set and current embedding/configuration authority still match the authoritative eligible set, then performs another fenced single-pointer activation. Legacy candidate and verification enum/table archaeology may remain for old records, but current producers do not write it and unfinished legacy jobs are terminalized.

Synchronous Personal Memory reads use short transaction-local, class-specific statement and lock budgets below their application settlement windows. Database timeout is a bounded fail-soft signal for optional candidate lanes, never a synchronous retry trigger. Durable history-visibility mutations advance the existing bounded Memory or source authority counters; time-based suppression expiry remains a current-time canonical SQL predicate and does not require a counter write.

Successful Memory jobs may retain only the database-allowlisted, content-free integer work counters used by operational aggregates. The schema guard rejects unknown keys, text, identifiers, negative/fractional values, and oversized payloads even from raw SQL. Operator snapshots expose bounded reason codes, counts, distributions, latencies, pending ages, and complete provider-reported usage totals only; they are not a product-facing run-inspection surface. Account deletion inventories and removes every account-owned Memory dependency, entity/alias support, staging, receipt, and operational owner while preserving only the inert default-settings exception.

Custom checks own row shape and bounded values; triggers own deferred cross-row, tenant/source, history, deletion, and concurrent-writer invariants that Prisma relations or repository validation cannot express alone. Keep them at the database boundary while raw SQL workers and destructive handlers exist, and simplify them only through behavior-proven append-only migrations.

Bootstrap runs under a serializable transaction and advisory lock. It accepts only an empty schema or the exact adopted administrator identity, refuses other nonempty targets before mutation, and creates minimal installation foundations without demo content or real provider deployments. Adopted reruns may repair missing code-owned foundations but preserve operator identities, credentials, settings, grants, policy choices, and content.

One active `preparing | queued | streaming | in_progress` run per chat is enforced in PostgreSQL. Eligible Normal personal run admission commits the message graph, exact ordinary bindings, private preparation state, and Memory attempt together; dispatch becomes possible only after the second guarded commit freezes the recovery request. Temporary and Project admission creates no Memory attempt, binding, item, receipt, or content-bearing Memory row. Terminal writers, tool results, external Memory executions, queue claims, and deletion work use status/version/lease guards so one transition wins.

Background document and Memory queues use durable owner-aware claims, short leases, heartbeats, and idempotent settlement. Fairness is per pipeline and non-preemptive; it prevents one continually eligible owner from monopolizing grants but is not an admission quota. Outcome-ambiguous external side effects are never blindly replayed.

Knowledge parsing persists an immutable, bounded normalized artifact that is sufficient to regenerate structural passages without the original object or parser service. Its schema preserves bounded workbook/sheet identity, typed cells, cached formulas, formats, hidden regions, merges, inferred headers/table regions, form/key-value graph identity and edges, original reading order, confidence, image/diagram/chart assets, OCR text, page/section relationships, bounding boxes, and safe warnings; older artifacts upgrade only in memory. The immutable hierarchical passage projection may additionally bind a document-local row/field locator and typed observation context, while Source and Version stay in relational evidence identity rather than parser JSON. These normalized forms participate only as ordinary indexed text and attributable citation context during focused answering. Citation reads resolve the exact stored Source Version/artifact and locator rather than relying on a second mutable projection.

A usable partial parse is a ready artifact with bounded safe warning codes, not a failed job. Replacement content becomes current only in the same guarded settlement that proves all expected chunks; retry exhaustion or worker recovery leaves the prior ready version current. Embeddings may be reused only for an exact embedding-text hash in the same vector space and dimension, and reused vectors do not create provider usage.

Each Source/Profile artifact may own a separately versioned immutable hierarchical index containing document, section, passage, and exact rows; building or backfilling it never rewrites the accepted parent artifact or V1 receipt. PostgreSQL remains the exact, metadata, document/section, and pgvector-dense authority. A durable projection obligation binds each current ready hierarchical artifact to the exact versioned OpenSearch mapping, canonical checksum, and expected passage count. Passage BM25 is usable only after that obligation is `READY` with a matching fingerprint and count; there is no PostgreSQL passage-FTS fallback. OpenSearch results are identities and scores until PostgreSQL revalidates the accepted owner, run, Base, generation, revision, snapshot, passage, and content hash. The mandatory vector lane remains qualified by the same accepted predicates, and database execution settings are transaction-local. Exact body operations require an explicit owner/artifact scope, reject unsafe patterns before database work, run under a statement timeout, scan at most 4 MiB of complete passages, and report when that bound truncated the requested scope.

Personal Memory lexical projection work is captured transactionally from canonical `MemorySearchEntry` mutations into an owner-ordered, content-free PostgreSQL outbox. Projection and terminal purge obligations deliberately survive deletion of their source rows. OpenSearch receives only minimal safe search documents under HMAC-derived routing and opaque identities; monotonic database sequence values prevent stale retries from resurrecting content. A generation is ready only after refresh visibility, compatible contract fingerprints, exact active Memory revision, and aggregate count/content-hash checks agree with PostgreSQL. Rebuild preflights the fresh replacement target and cluster compatibility before resetting derived PostgreSQL readiness, writes that fresh physical index, and changes read/write aliases atomically only after the full integrity proof; a rejected preflight leaves the serving projection and its readiness intact. Restore invalidates derived readiness and reconstructs obligations from PostgreSQL. Shadow, canary, and primary reads recheck this PostgreSQL-owned readiness row and rejoin every hit through canonical selectors. Only canary/primary may return those canonicalized candidates; dirty, incompatible, unavailable, or canonically impossible projection results use the retained PostgreSQL lexical provider without repairing canonical state from OpenSearch.

`npm run knowledge:sources:backfill` reconciles the additive V1-to-Source bridge in bounded serializable batches. It is safe to rerun after interruption and emits counts only; it neither reads object bytes nor infers that equal file checksums are one Source.

## Retention And Deletion

`npm run prune -- --dry-run` is read-only and precedes any explicitly authorized `--execute`. Pruning removes only bounded terminal/auth state and stages private-object cleanup. It never deletes active sessions, live accepted runs, retrieval-visible Knowledge payloads without a proven cutoff, or an object still referenced by Attachment or Knowledge.

Object deletion uses a durable per-key job. Staging locks and rechecks all references; workers claim bounded leases; deletion is idempotent; failures retain a retryable obligation with a stable value-free code. Run attachment linking uses the inverse compare-and-set so a prune/run race has one transactional winner.

Knowledge Trash is an immediate future-admission fence while membership and publication state remains recoverable; Trash and Restore are idempotent optimistic transitions. Permanent deletion is admitted only from Trash and creates a durable relational job before acknowledging the request. Source purge removes every Version, artifact, membership, and private payload, while Base purge removes the Base scope and its accepted evidence without deleting canonical Sources. Historical generated answer text remains, but deleted retrieval evidence is reduced to a generic citation handle with no filename, excerpt, locator, asset, or private identifier; even empty-result receipts replace their final deleted-Base evidence with a value-free tombstone. Each storage key is deleted only after a reference recheck, and the relational job cannot succeed until every object obligation is deleted or proven retained by another live resource. Settled per-object manifests are then discarded so completed audit state does not retain object paths or filenames. Prune permanently stages Knowledge left in Trash for the default 30-day retention period, releases object and multipart authority from upload sessions expired for more than seven days while preserving a retryable value-free receipt, and resumes both relational and object obligations.

Temporary chat expiry, permanent retained-chat deletion, account Memory cleanup, reusable-Memory deletion, and scope-target deletion are typed aggregate obligations. Admission first fences future recall/work/sharing, then retry-safe handlers settle active work and remove only the authorized aggregate. Deletion obligations may become visibly administrator-blocked but are never abandoned. Provider, external tool, backup, and already-sent Search/embedding retention are not falsely promised as erased.

Project deletion is an explicit Owner-authorized aggregate transition that removes Project-owned content and bindings under database ownership rules; removing Project Base bindings does not delete a member's personal Source or Base. Account deletion stages and drains every owned Knowledge Source and Base obligation before deleting the user. Deleting an individual account does not substitute for deleting a Project, and Project archival does not rewrite accepted evidence.

## Backup And Restore

`ops/backup/create.sh` is the Postgres/object consistency boundary. It verifies the migrated schema, stops app and Memory writers, releases or fences claimed Memory, Knowledge, and object-deletion work, copies both authorities, records format/schema and required non-secret Memory key IDs, then restores exactly the prior writer set. OpenSearch is deliberately excluded from the backup authority: its volume is disposable derived state.

Restore accepts only an acknowledged empty internal `aiqsa-restore-*` project with no published ports and no application writer. It preflights format, schema, identities, keys, and objects before producing a pending review manifest. Review runs credential-free Memory and Knowledge deletion reconciliation, resets restored search obligations to pending, and blocks promotion while deletion/account/barrier duties, leases, uncertain executions, missing keys, or object failures remain. Fresh OpenSearch projections must be rebuilt from canonical PostgreSQL and pass their strict aggregate integrity gates before their respective retrieval modes are enabled. Helpers never cut over production automatically.

All destructive verification targets only the disposable topology described in [Testing](TESTING.md). Security and secret boundaries are in [Security](SECURITY.md).
