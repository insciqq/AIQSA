# PERSISTENCE

Owner: Persistence maintainers
Scope: Durable ownership, migrations, retention, backup, restore, and deletion obligations.

## Authority And Shape

`prisma/schema.prisma`, committed migrations, database constraints, repositories, and stateful tests own exact tables and fields. Prose records only cross-aggregate rules. PostgreSQL is the coordination authority for users, entitlements, chats/message DAGs, immutable configuration revisions, accepted runs/bindings, jobs, usage, Memory, Knowledge, MCP, and share snapshots. The installation Knowledge Profile uses an optimistic active pointer over append-only, database-immutable revisions; generation rows retain their exact profile identity, and pointer changes affect future work without rewriting accepted bindings or existing generations. Private object bytes live in the configured S3-compatible store or filesystem fallback; relational rows own capability and lifecycle.

Tenant-bearing parents and children prove the same owner at the database boundary wherever representable. Accepted revisions, bindings, content generations, and recovery evidence are immutable and restrictive while referenced. Mutable recommendations, preferences, and drafts grant no entitlement. Null, explicit Off, and a concrete choice remain distinct persisted states.

Knowledge Source identity is independent of Base membership. A canonical owner-scoped Source owns append-only immutable Source Versions; processing identity is reused per exact Source Version and immutable Knowledge Profile revision, and a ready artifact cannot be rewritten. Bases retain soft-removable membership history, while each accepted run binds an immutable Base snapshot containing the exact ready Source Version/artifact evidence available at admission. Membership, current-version, and profile changes create different future evidence and never rewrite an older snapshot. The V1 bridge uses explicit one-document/one-version mappings and never merges equal checksums; its application backfill is content-free, resumable, idempotent, and reports aggregate reconciliation only. Old V1 bindings remain readable through the nullable snapshot bridge.

One Evidence v2 retrieval session belongs to one model run. Retrieval operations may share deduplicated evidence items, but stable handle ordinals are allocated under the run lock and never encode an operation or Base. Terminal answer settlement hashes the complete private package and seals the session, evidence items, operation receipts, and provenance against later writes at both repository and database boundaries. Permanent Knowledge purge is the sole mutation capability: in the same transaction it clears every identity, label, excerpt, boundary, and locator from affected items, preserves only the handle/tombstone state, redacts the scope snapshot, and replaces the sealed hash. Ordinary API and log projections never include this receipt or its text.

Personal and Project ownership are disjoint principals. A Project child is owned through `projectId`, never through the member who created or uploaded it, so account deletion removes that member's grants without deleting the shared aggregate or abandoning attachment processing. Mutable actor references may become null while bounded display-name/role snapshots preserve authorship and audit meaning. Canonical Project model/Search/MCP bindings and Knowledge/Assistant/Skill publications are scoped authorities distinct from personal grants; accepted Project run bindings preserve the initiating identity, exact access, instructions, policy, Memory, resource revisions, and installation/shared credential evidence needed for recovery. Database constraints and deferred triggers enforce owner/source consistency and at least one direct active Owner, including concurrent grant changes.

Skill definitions own immutable text revisions plus group/installation publications. Publications are live grants on the definition: future discovery and admission resolve the current revision, while every accepted run binds the exact revision it received. Immutable Assistant revisions may own ordered relational links to Skill definitions, never to Skill revisions; this keeps the Assistant list stable while future runs receive each Skill's current text. An Assistant publication is valid only when every linked Skill directly reaches the same audience, and removing a Skill publication is blocked when no remaining publication covers an affected published Assistant audience. Deleting a Skill tombstones the definition and transactionally removes its publications and all Assistant links without deleting revisions or accepted bindings; recovery of a finally accepted run does not recheck current publication or tombstone state. A publication never grants executable or MCP authority. Auto MCP discovery similarly freezes its schema-free catalog and monotonic discovery epochs inside the accepted recovery request while exact materialized server generations remain relational run bindings. Each epoch is identified by its persisted `ModelRunToolCall`, including an empty selection, so equal goals remain independent calls and recovery never uses goal text as an idempotency key.

The protected non-archived `Full access` group has explicit membership and semantically receives every current/future active provider connection, answer model, and Search source without materialized ordinary grants. Its name and lifecycle are immutable. MCP use remains materialized per server so deletion and revision policy retain exact relations; it never grants personal slots, OAuth identity, or personal secrets. Ordinary grants require exactly one principal and one nonempty target.

Persist run or tool data only for execution, recovery, duplicate-side-effect prevention, security, deletion, citations/generated output, retention, or aggregate accounting. Presentation-only event histories, previews, and inspector payloads are not storage justification. Remove a projection first, prove recovery consumers, stop writes, then remove schema with a forward migration.

Project synchronization uses a bounded durable outbox inserted with the authoritative mutation. Its monotonic opaque cursor, Project identity, event category, affected identity/version, and timestamp support ordering and reconnect; rows contain no secret, attachment content, private resource label, retrieval text, tool arguments/results, or browser projection. Current safe state is serialized from authoritative tables at delivery. PostgreSQL notification is only a post-commit wake-up signal, never the durable source, and retention expiry produces an explicit canonical resync.

## Migrations And Bootstrap

`20260815000000_baseline` is the immutable first migration anchor; its reviewed custom PostgreSQL DDL is part of the contract and cannot be reconstructed from Prisma alone. Future changes are append-only migrations. Persistent installations use `prisma migrate deploy`, never `prisma db push`.

Custom checks own row shape and bounded values; triggers own deferred cross-row, tenant/source, history, deletion, and concurrent-writer invariants that Prisma relations or repository validation cannot express alone. Keep them at the database boundary while raw SQL workers and destructive handlers exist, and simplify them only through behavior-proven append-only migrations.

Bootstrap runs under a serializable transaction and advisory lock. It accepts only an empty schema or the exact adopted administrator identity, refuses other nonempty targets before mutation, and creates minimal installation foundations without demo content or real provider deployments. Adopted reruns may repair missing code-owned foundations but preserve operator identities, credentials, settings, grants, policy choices, and content.

One active `preparing | queued | streaming | in_progress` run per chat is enforced in PostgreSQL. Run admission commits the message graph, exact ordinary bindings, private preparation state, and Memory attempt together; dispatch becomes possible only after the second guarded commit freezes the recovery request. Terminal writers, tool results, external Memory executions, queue claims, and deletion work use status/version/lease guards so one transition wins.

Background document and Memory queues use durable owner-aware claims, short leases, heartbeats, and idempotent settlement. Fairness is per pipeline and non-preemptive; it prevents one continually eligible owner from monopolizing grants but is not an admission quota. Outcome-ambiguous external side effects are never blindly replayed.

Knowledge parsing persists an immutable, bounded normalized artifact that is sufficient to regenerate structural passages without the original object or parser service. Its current schema also preserves bounded workbook/sheet identity, typed cells, cached formulas, formats, hidden regions, merges, inferred headers/table regions, image/diagram/chart assets, page/section relationships, bounding boxes, and safe warnings; older artifacts upgrade only in memory. A usable partial result is a ready artifact with bounded safe warning codes, not a failed job. Replacement content becomes current only in the same guarded settlement that proves all expected chunks; retry exhaustion or worker recovery leaves the prior ready version current. Embeddings may be reused only for an exact embedding-text hash in the same vector space and dimension, and reused vectors do not create provider usage.

Structured answers persist the decoded plan, operation summary, exact input ranges, bounded result, and formula/hidden-row counters inside the immutable Evidence v2 item. Citation reads reconstruct cells from the same checksummed normalized artifact rather than persisting a second workbook projection. Ambiguous structured requests persist their bounded clarification questions in the retrieval session so terminal grounding returns those questions exactly and cannot replace them with a model guess.

Visual answers persist the selected immutable block/asset locator, page boxes, caption, analysis availability, bounded description, and provider usage inside Evidence v2. Citation reads resolve that exact block from the same checksummed normalized artifact and authorize the original object at read time; no second mutable visual index or provider payload is stored.

Each Source/Profile artifact may own a separately versioned immutable hierarchical shadow containing document, section, passage, and exact rows; building or backfilling that shadow never rewrites the accepted parent artifact or V1 receipt. Weighted `simple`, English, and Russian FTS vectors are generated and GIN-indexed in PostgreSQL, while trigram tolerance is limited to filename/title/heading/tag metadata. Exact body operations require an explicit owner/artifact scope, reject unsafe regex before database work, run under a statement timeout, scan at most 4 MiB of complete passages, and report when that bound truncated the requested scope.

Vector retrieval chooses exact scan or ANN from the accepted scope's measured eligible-row count. ANN uses a generated deterministic Base bucket and dimension-specific partial HNSW indexes so PostgreSQL can qualify filtered plans without making the bucket an authority or tenant boundary; user, run, Base, generation, revision, and snapshot predicates remain mandatory. Planner settings are transaction-local, and plan/parity evaluation covers every supported vector dimension before a layout is accepted.

`npm run knowledge:sources:backfill` reconciles the additive V1-to-Source bridge in bounded serializable batches. It is safe to rerun after interruption and emits counts only; it neither reads object bytes nor infers that equal file checksums are one Source.

## Retention And Deletion

`npm run prune -- --dry-run` is read-only and precedes any explicitly authorized `--execute`. Pruning removes only bounded terminal/auth state and stages private-object cleanup. It never deletes active sessions, live accepted runs, retrieval-visible Knowledge payloads without a proven cutoff, or an object still referenced by Attachment or Knowledge.

Object deletion uses a durable per-key job. Staging locks and rechecks all references; workers claim bounded leases; deletion is idempotent; failures retain a retryable obligation with a stable value-free code. Run attachment linking uses the inverse compare-and-set so a prune/run race has one transactional winner.

Knowledge Trash is an immediate future-admission fence while membership and publication state remains recoverable; Trash and Restore are idempotent optimistic transitions. Permanent deletion is admitted only from Trash and creates a durable relational job before acknowledging the request. Source purge removes every Version, artifact, membership, and private payload, while Base purge removes the Base scope and its accepted evidence without deleting canonical Sources. Historical generated answer text remains, but deleted retrieval evidence is reduced to a generic citation handle with no filename, excerpt, locator, asset, or private identifier; even empty-result receipts replace their final deleted-Base evidence with a value-free tombstone. Each storage key is deleted only after a reference recheck, and the relational job cannot succeed until every object obligation is deleted or proven retained by another live resource. Settled per-object manifests are then discarded so completed audit state does not retain object paths or filenames. Prune permanently stages Knowledge left in Trash for the default 30-day retention period, releases object and multipart authority from upload sessions expired for more than seven days while preserving a retryable value-free receipt, and resumes both relational and object obligations.

Temporary chat expiry, permanent retained-chat deletion, account Memory cleanup, reusable-Memory deletion, and scope-target deletion are typed aggregate obligations. Admission first fences future recall/work/sharing, then retry-safe handlers settle active work and remove only the authorized aggregate. Deletion obligations may become visibly administrator-blocked but are never abandoned. Provider, external tool, backup, and already-sent Search/embedding retention are not falsely promised as erased.

Project deletion is an explicit Owner-authorized aggregate transition that removes Project-owned content and bindings under database ownership rules; removing Project Base bindings does not delete a member's personal Source or Base. Account deletion stages and drains every owned Knowledge Source and Base obligation before deleting the user. Deleting an individual account does not substitute for deleting a Project, and Project archival does not rewrite accepted evidence.

## Backup And Restore

`ops/backup/create.sh` is the Postgres/object consistency boundary. It verifies the migrated schema, stops app and Memory writers, releases or fences claimed Memory, Knowledge, and object-deletion work, copies both authorities, records format/schema and required non-secret Memory key IDs, then restores exactly the prior writer set.

Restore accepts only an acknowledged empty internal `aiqsa-restore-*` project with no published ports and no application writer. It preflights format, schema, identities, keys, and objects before producing a pending review manifest. Review runs credential-free Memory and Knowledge deletion reconciliation and blocks promotion while deletion/account/barrier duties, leases, uncertain executions, missing keys, or object failures remain. Helpers never cut over production automatically.

All destructive verification targets only the disposable topology described in [Testing](TESTING.md). Security and secret boundaries are in [Security](SECURITY.md).
