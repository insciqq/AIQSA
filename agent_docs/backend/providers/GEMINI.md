# NATIVE GEMINI INTERACTIONS RUNTIME

Owner: Provider runtime maintainers
Scope: Current AIQSA runtime behavior for the native Gemini Interactions adapter and hosted grounding fence.
Read when: Changing Gemini setup, request/response mapping, signatures, attachments, function tools, hosted Search, grounding display, or live-only persistence.
Code owners: `lib/server/providers/geminiInteractions*.ts`, grounding persistence, and Gemini runtime construction.
Not owned here: Upstream Gemini facts, shared admission, or provider-neutral Search execution.

## Native Gemini Interactions

Gemini is a first-class provider family over the stable native root `https://generativelanguage.googleapis.com/v1`; runtime calls only `POST /interactions` with `x-goog-api-key`. Quick and Advanced catalog tests use the native key header, call the bounded v1 Models catalog, reject unexpected pagination, and strip only the returned `models/` prefix before exact policy/configuration comparison. The current reviewed Gemini Quick Setup candidates are Gemini 3.6 Flash, 3.5 Flash, 3.5 Flash-Lite, and 3.1 Pro Preview; arbitrary catalog rows are never promoted to deployments, and existing installations are not backfilled with new answer models.

`gemini_interactions_native` is the only adapter accepted for the Gemini family. `geminiInteractionsRequest.ts` builds `store: false` AIQSA-owned history, native user/model content and attachments, `generation_config`, hosted/function tools, and always-redacted previews. `geminiInteractionsTransport.ts` owns the native endpoint/key header and bounded response reads. `geminiInteractionsResponse.ts` owns native JSON/SSE terminal proof, steps, usage, function calls, and grounding normalization; `geminiInteractionsGrounding.ts` owns the strict Search-Suggestions markup parser. None of these modules calls or retries through the generic compatible transport.

Gemini consumes the shared prior-turn marker projection from [runs and
streaming](../RUNS_AND_STREAMING.md). An attachment-only turn whose
native/extracted payload produces no content also uses that projection instead
of emitting an empty native text part.

Native SSE starts with one valid `interaction.created`, accepts bounded ordered step start/delta/stop and status events, and succeeds only after a completed/requires-action terminal interaction plus the final native `done` event. Optional fields serialized as explicit `null` are treated as absent, matching JSON provider behavior; required fields and non-null wrong types remain strict. A thought or Google Search call/result may carry `signature: ""` only in `step.start`; that value is provisional and a later signature delta must supply the normal bounded non-empty signature before `step.stop`. Empty signature deltas, malformed functions, and an unfinished provisional signature remain invalid. EOF, failed/cancelled/incomplete state, missing/duplicate/unordered/unfinished steps, malformed arguments/signatures/usage, mismatched terminal text, or trailing data fails safely. Normalized usage maps total input/cached/thought/output/total fields, adding thought tokens to AIQSA output so reasoning remains its subset.

Custom functions use the existing provider-neutral bounded tool loop. Interactions function/thought steps are replayed exactly; thought signatures stay only in the private `toolLoopState` checkpoint and next wire request, while public events/previews/logs/UI redact them. Google documents a Gemini 3 preview path that combines built-in Google Search with custom functions through validated tool-context circulation, but the current AIQSA adapter does not implement that lifecycle. AIQSA admission intentionally prevents hosted Gemini Search and provider-neutral client/MCP functions from sharing one answer request and selects the separate query-only Gemini client route when coexistence is required. Supporting the preview path would require a separate reviewed implementation of its tool-choice, signature, continuation/recovery, hosted-retention, MCP-coexistence, and provider-verification contracts. The native adapter supports image, PDF, and extracted-document inputs only when the selected deployment advertises the corresponding capability.

When the admitted physical route is hosted, selected `gemini-google-search` adds only `{ type: "google_search" }` to that Gemini answer request. If the model never calls it, the ordinary answer contract applies. At the first actual hosted search step, execution enters irreversible grounded live-only mode. Stream text is buffered until the provider supplies non-empty Suggestions that pass the server parser; after complete structural validation the server removes every provider `<style>` node, and the live `grounding_display` containing bounded call/query counts, safe transient citations, and the bounded canonical style-free projection is delivered before the first answer token. Missing/unsafe Suggestions fail without releasing answer text. A ShadowRoot browser component applies a second structural allowlist and uses repository-owned styles for the observed bounded Google HTTPS markup shape.

The hosted grounding marker atomically disables token/artifact persistence and purges any pre-marker drafts. Completion/failure stores only explicit message provenance, a neutral content/preview placeholder, normalized usage/status, and a sanitized error when applicable. Hosted grounded answer text, Suggestions, citation Links, search results/signatures, and provider markup never enter `Message`, `ModelRunEvent`, previews, logs, later provider context, or share snapshots. The final live `chat_update` retains the answer only for the current in-memory thread; reload shows the placeholder and public-share creation rejects that visible branch. This live-only answer rule is intentionally separate from the client Search result contract above, which retains only its adapter-normalized findings and citations.
