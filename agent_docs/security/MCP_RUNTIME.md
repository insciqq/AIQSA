# SECURITY — MCP RUNTIME TRUST

Owner: Security and privacy maintainers
Scope: Remote and local MCP authorization, source trust, runtime identity, ToolHive ownership, retention, and evidence boundaries.
Read when: Changing MCP OAuth, source admission, local workloads, ToolHive lifecycle, runtime cleanup, grants, tokens, or tool evidence.
Code owners: `lib/server/mcp/`, MCP routes, and ToolHive runtime integration.
Not owned here: General HTTP auth, upload processing, provider catalogs, or dependency installation.

## MCP Runtime Trust

Only active administrators may manage or grant MCP servers. This prevents ordinary installation; it does not make selected code safe. A grant covers one server, whose active revision may disable bounded exact case-sensitive names installation-wide. Other current/new valid names, including state-changing tools, default enabled with no per-call approval. Enabled servers share model context; data/results may reach another tool.

Normal **Activate** is the trust decision for that revision's enabled subset. It persists a bounded job and returns before validation; policy edits require full discovery validation and a new immutable activation. The job never makes a draft usable. Publication rechecks the job/claim, draft hash, shared-value version, live server, and validation identity, retaining codes/paths instead of raw output. Superseded work may clean up but cannot publish. Live opaque workload tokens block orphan cleanup: activation tokens are durable; synchronous local Test, Check update, and Rebuild tokens are process-local. Request-only values stay within synchronous Test.

Security validation runs against the complete sanitized discovery before policy
filtering, including disabled and temporarily missing names, and rejects an
inventory containing an exact known credential. Dispatch independently applies
the accepted generation's exact-name fence before settlement or MCP I/O.
[Core pipeline](../run_pipeline/CORE_PIPELINE.md) owns effective-subset
publication, accepted snapshots, and future-only policy activation.

Remote Streamable HTTP MCP requests use the pinned official SDK behind AIQSA's SSRF-safe fetch and administrator-owned OAuth/static-header policy. The stored endpoint URL is administrator-visible non-secret configuration and rejects URL userinfo, query strings, and fragments; path segments may carry ordinary routing/resource identifiers but must not contain credentials. Providers requiring a secret in the URL are unsupported until a dedicated encrypted binding exists; use an encrypted static-header slot or OAuth instead. The administrator-selected MCP endpoint origin is the narrow fallback authorization origin when no separate origin was declared; any cross-origin authorization server must be added explicitly and is never accepted merely because untrusted discovery advertised it. A missing protected-resource override may bind only a canonical same-origin resource returned by discovery; explicit and cross-origin resources retain exact reviewed matching, so this path rule never broadens origin trust. Static and OAuth credentials remain encrypted in AIQSA storage and are not sent to ToolHive in normal operation. Browser OAuth initiation is an authenticated same-origin GET navigation, with protected POST retained for compatible clients; callback GETs require the short-lived HttpOnly flow cookie plus exact state/PKCE binding and derive their URL from `AIQSA_APP_BASE_URL`. This preserves CSP `form-action 'self'` while allowing normal top-level navigation to the reviewed remote authorization endpoint. Access/refresh tokens, codes, verifiers, raw provider errors, and unrestricted account data never enter callback query output or application logs. Lost entitlement/admin eligibility and a changed active OAuth-policy fingerprint asynchronously drain the affected connection and best-effort revoke it; merely disabling use preserves authorization for a later re-enable.

Remote MCP JSON/SSE is bounded before SDK parsing; overflow closes the affected
transport and cannot retain a partial envelope. Public errors and durable
previews never include the body, arguments, endpoint, headers, credentials,
parser details, or a partial result. Structured warnings may retain only the
bounded operation/limit/transport and opaque run-correlation projection.
[Runs and streaming](../backend/RUNS_AND_STREAMING.md) owns stable error-code,
retry, and continuation effects; [environment variables](../ENV_VARIABLES.md)
owns configurable sizes and hard ceilings.

A brokered remote MCP is two trusted OAuth domains, not token passthrough. AIQSA accepts only opaque tokens for the exact MCP resource/client/scope policy; upstream SaaS tokens stay encrypted inside the remote MCP, and local/Yandex/Google identity does not authorize an upstream actor. The remote MCP remains administrator-trusted code with upstream credential/data access. Its grant exposes only the active revision's enabled subset. Tool annotations are not authorization or per-call approval; the first brokered deployment remains read-only.

Local npm, PyPI, and digest-pinned OCI stdio MCPs run in separate ToolHive-created sibling containers. The pinned ToolHive controller alone mounts `/var/run/docker.sock`; neither the app nor an MCP workload receives it, and the controller/proxy APIs are confined to the private `mcp-control` network. Docker socket authority is nevertheless effectively root authority over the host. The application can reach ToolHive's full unauthenticated private API, so application compromise is transitively host compromise. Dropped capabilities, a read-only controller filesystem, opaque ownership names, and sibling workload isolation reduce accidental exposure but do not change that accepted trust boundary.

Local MCP workloads have ordinary outbound network access. They do not join the application data network and receive no AIQSA database/session/provider/SMTP/storage credential by design, but a malicious workload can use or exfiltrate any explicit value it receives and any tool input the model supplies. Install only reviewed MCP servers and treat their output/stderr as untrusted. After a failed draft startup AIQSA may read only a bounded ToolHive log response, recognize a narrow safe pattern such as a missing uppercase environment-variable name, and discard the text; raw or unclassified workload output is never persisted or returned to a user/admin response.

AIQSA encrypts administrator/shared values, personal values, OAuth tokens, and effective runtime snapshots at rest with `AIQSA_ENCRYPTION_KEY`; secret API fields are write-only. Removed or unknown slot keys are never selected for effective configuration or returned to the browser, although the initial release does not rewrite existing envelopes solely to erase those inactive encrypted entries. For local environment bindings, the selected plaintext is then sent as ordinary ToolHive `env_vars` and is visible in ToolHive state plus Docker container metadata to the application, controller, Docker daemon, and host administrators. Docker does not encrypt environment variables. Draft validation and live reconciliation reject a complete serialized tool inventory if it contains an exact known static, personal, or OAuth credential. Runtime/run evidence may retain only the source category (`oauth`, `personal`, or `shared`) and a bounded provider-supplied account/workspace label, never the value. Logs and user/admin responses must not contain workload requests, process environments, OAuth material, or known secret values; ToolHive state, Docker diagnostics, and backups are sensitive installation data.

Dynamic MCP containers are outside the Compose project. Normal reconciliation drains exact AIQSA-owned generations, and `npm run mcp:cleanup`/the `mcp-maintenance` Compose service defaults to listing only workloads that match the installation's opaque group and strict generation-name marker. `--execute` is the only destructive mode; it verifies no exact-owned workload remains and refuses to delete an unknown group member. The marker derives from `AIQSA_ENCRYPTION_KEY`, so planned cleanup must run before key replacement or loss.
